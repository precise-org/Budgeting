# ระบบขอเบิกใช้งบประมาณ — สรุปการทำงานปัจจุบัน (เพื่อทบทวน)

สรุปจากโค้ดเวอร์ชัน `2026.11.15-2` (ต้นแบบ) — อ่านแล้วบอกได้ว่าข้อไหนไม่ตรงกับงานจริง หรืออยากให้ปรับ
ท้ายเอกสารมีหัวข้อ **"จุดที่ควรทบทวน"** รวบรวมสิ่งที่ผมไม่แน่ใจ หรือที่ผมตัดสินใจเองไว้

## 1. ภาพรวมและข้อจำกัดของต้นแบบ

- เว็บ HTML / CSS / JavaScript ล้วน เปิดที่ GitHub Pages ไม่มีเซิร์ฟเวอร์
- **ข้อมูลเก็บในเบราว์เซอร์ของแต่ละคนเท่านั้น** (`localStorage`) — ไม่แชร์ข้ามเครื่อง ล็อกอินเป็นแค่การจำลองขั้นตอน (ดูหัวข้อ 12) ไม่เชื่อม Supabase
- มีเมนูมุมขวาบนสลับผู้ใช้ตัวอย่าง 8 คน: สมชาย / สุดา (Business), พิมพ์ (ธุรการ), มาลี / วิภา (ผู้คุมงบ), นิดา (บัญชี), ปิติ (จัดซื้อ), อดิศร (Admin)
- เริ่มต้นเป็น**ระบบว่าง** (มีข้อมูลหลักตั้งต้น: บริษัท PBI / PCC, หน่วยงาน, กลุ่มรายการ, กลุ่ม Priority, Supplier) · เมนูผู้ใช้มี "โหลดข้อมูลตัวอย่าง" และ "ล้างข้อมูลทั้งหมด (เริ่มทดสอบ)"
- ไฟล์แนบ (PDF / PNG / JPG) เก็บในเบราว์เซอร์ จำกัด 400 KB ต่อไฟล์ · คลิกชื่อไฟล์เพื่อเปิดดูในหน้าเว็บได้
- ไม่มีการแจ้งเตือน (อีเมล / LINE) — ดูงานที่รอได้ที่เมนู "งานทั้งหมด"

## 2. บทบาทและสิทธิ์

| บทบาท | ทำอะไรได้ |
|---|---|
| **Business** (ผู้ขอใช้งบ) | ขออนุมัติงบใหม่ (CAPEX / OPEX) · เปิดใช้งบที่ผู้คุมงบลงไว้ (CAPEX) · เบิกใช้งบ · ขอเพิ่มงบ · เพิ่ม Item ย่อย OPEX · วาง Plan Cashflow — **เฉพาะงบที่ตนเป็นเจ้าของ** เห็นเฉพาะงบของตน |
| **ผู้คุมงบ** | ลงงบประจำปี (สร้าง / Import Excel) · ตรวจและยืนยันเปิดใช้งบ · ตรวจ/อนุมัติ/ส่งกลับการเบิกใช้งบ · ยืนยันยอดและปิดยอด PR/PO (ตัดงบสำรองจ่าย / จ่ายตรงอัตโนมัติตอนอนุมัติ) · โยกงบ / ลดงบ · ยืนยันเพิ่มงบ · ส่งออก Excel · เห็นทุกงบ |
| **จัดซื้อ** | ดูทุกงบ · บันทึก PR / PO ของการเบิกแบบ PR/PO |
| **บัญชี** | ดูงบของบริษัทที่มีสิทธิ์ · **ใส่ / แก้ GL Code ของ OPEX** ที่เมนู "จัดการ GL" ตั้งแต่ Business ขอเปิดงบ (ไม่ต้องรอเปิดใช้งบ) · ส่งออก Excel · **ไม่ใช่ผู้คุมงบ** (ตรวจ / ยืนยัน / ตัดงบไม่ได้) |
| **Admin ผู้ช่วย Business (ธุรการ)** | ทำเอกสารแทน Business ได้ทุกอย่าง **ในบริษัทที่มีสิทธิ์ — ถ้า Admin แท็กไว้ จะเฉพาะ Business ที่แท็ก** (ช่อง "ช่วยงานให้ Business" ในหน้าผู้ใช้ — เลือกได้หลายคน · ธุรการแก้เองไม่ได้ · **ยังไม่ได้แท็กใครเลย = เห็นและทำแทนได้ทั้งบริษัทไปก่อน** · ฐานข้อมูลบังคับ `v2_profiles.proxy_for` + บริษัทที่มีสิทธิ์) (สร้างงบ — เลือก Business เจ้าของงบ, ขอเบิกใช้งบ, ขอเพิ่มงบ, Plan Cashflow, Item ย่อย OPEX) โดยเอกสารเป็นของ Business เจ้าของงบ และบันทึก "ทำแทนโดย" · **เปิดใช้งบครั้งแรกไม่ได้** (ต้องเป็น Business เจ้าของงบเท่านั้น — บล็อกทั้งหน้าเว็บและฐานข้อมูล) |
| **Admin** | ข้อมูลหลัก · Log ทั้งระบบ · ผู้ใช้และสิทธิ์ · ส่งออก Excel · ดูงบได้ทั้งหมด **แต่ไม่ทำรายการ** |

สิทธิ์เป็นรายข้อ (15 ข้อ — เพิ่ม `business.proxy` ทำเอกสารแทน Business และ `gl.manage` ใส่ GL) ผู้ดูแลติ๊กสิทธิ์ของแต่ละบทบาทและสร้างบทบาทเพิ่มได้ที่เมนูซ้าย "ผู้ดูแลระบบ → บทบาทและสิทธิ์" (โหมดทดลองเก็บในเบราว์เซอร์ คีย์ `procurement.v5.roles` · Admin ต้องมี `user.manage` เสมอ · ลบได้เฉพาะบทบาทที่สร้างเพิ่มและไม่มีผู้ใช้ใช้อยู่)

## 3. เมนูและหน้า

เมนูซ้ายเรียงตามนี้ (แสดงตามสิทธิ์): **งบประมาณ** (หน้าแรก) → งานทั้งหมด → รายการเบิกใช้งบ → ประวัติการทำรายการ → **จัดการ GL** (เฉพาะบัญชีที่มีสิทธิ์ใส่ GL — รายการงบ OPEX ที่ใส่ GL ได้ แยกยังไม่ครบ / ครบแล้ว) → ส่งออกข้อมูล (Excel) → **รายงาน** → กลุ่ม **ผู้ดูแลระบบ** (ต่อจากรายงาน แสดงเมนูละรายการตามสิทธิ์): **ผู้ใช้** (มีตัวเลขแดงเมื่อมีบัญชีขอรีเซ็ตรหัสผ่าน) · **บทบาทและสิทธิ์** · **ข้อมูลหลัก** (มีเมนูย่อย) · **Log การทำงาน**

- **งบประมาณ**: ชื่อหน้า + ปุ่มหลักชิดขวา → การ์ดตัวเลข 4 ใบ (จำนวนงบ · งบที่ได้รับอนุมัติ · ตัดงบแล้ว+จองไว้ · คงเหลือ — เปลี่ยนตามตัวกรอง) → ตารางทะเบียนงบ (ค้นหา / กรองปี, บริษัท, หน่วยงาน, ประเภท, สถานะ / กดหัวคอลัมน์เรียง / แบ่งหน้า 50 งบ)
- **งานทั้งหมด**: รวมงานที่ต้องทำแยกเป็นแท็บตามบทบาท (ตัวเลขแดง = งานที่ต้องลงมือ)
- **รายงาน**: กรองปี / บริษัท / ประเภท · การ์ดตัวเลข · สรุปงบตามบริษัท / บริษัทที่ลงทุน / กลุ่มงบ / หน่วยงาน / ประเภท · กราฟตัดงบ 6 เดือนล่าสุด · งานที่ต้องทำ · งบที่ต้องจับตา (เกินงบ / เหลือไม่ถึง 10%)
- **ประวัติการทำรายการ**: สิ่งที่ตนทำ และที่ผู้อื่นทำกับงบ/เอกสารของตน · **Log การทำงาน**: ทั้งระบบ เฉพาะ Admin
- หน้า "สิ่งที่รอยืนยัน" ถูกเอาออกจากเมนู แต่ยังเปิดได้ที่ `#/assumptions`

## 4. ชนิดงบ

| | CAPEX (งบลงทุน) | OPEX (งบดำเนินงาน) |
|---|---|---|
| โครงสร้าง | **แยก Item** (มีรหัส ชื่อ วงเงินรวม VAT) หรือ **งบรวมทั้งโครงการ** (ไม่แยก Item เลือกหมวดค่าใช้จ่ายตอนเบิก) | **ต้องมี Item เสมอ**: Item หลัก (1, 2, 3 …) ตั้งตอนตั้งงบ ไม่มีจำนวน/หน่วย · Item ย่อยได้ 3 ระดับ (1 → 1.1 → 1.1.1) เพิ่มทีหลังได้ไม่จำกัด |
| ตั้งต้น | — | Item หลัก 4 รายการ: ต้นทุนวัตถุดิบ / ค่าแรง / ค่าเช่า / รายการส่วนเพิ่มอื่นๆ |
| วงเงิน | ก่อน VAT ไม่แยก — กรอกรวม VAT | ก่อน VAT + ติ๊ก VAT 7% |
| GL Code | — | ไม่บังคับ ฝ่ายบัญชี (ผู้คุมงบ) ใส่ทีหลังได้ (กรอกเป็นข้อความอิสระ) · Item ย่อยที่ว่างใช้ GL ของ Item แม่ |
| พิเศษ | Plan Cashflow (ประมาณการใช้เงินรายเดือน) | ผลรวม Item ย่อยต้องไม่เกิน Item หลัก (กำหนดวงเงิน Item ย่อยหรือไม่ก็ได้) |

- รหัสโครงการและรหัส Item **ผู้สร้างงบกรอกเอง** (ผู้คุมงบตอนลงงบ / Business ตอนขอเอง) ระบบไม่รัน
- ทุก Item ใช้งบของ**บริษัทเจ้าของงบ** (ไม่มีช่องบริษัทที่ลงทุนใน Item แล้ว)
- **ไม่มี DOA** ในระบบ (ตรวจสอบกันเองแบบ Manual)

## 5. วงจรของงบ

### 5.0 ขั้นตอนหลักและสถานะ (CAPEX / OPEX เหมือนกัน)

ผู้อนุมัติ (ผู้บริหาร / ที่ประชุม) **ไม่ได้ใช้ระบบนี้** — เซ็นเอกสารนอกระบบ ส่วนคนที่ตรวจและกดผ่าน / ส่งกลับในระบบคือ **ผู้คุมงบ**

**Business สร้างงบ — 3 ขั้น: สร้างงบประมาณ → อนุมัติ → เปิดใช้**

| ขั้นหลัก | สถานะ | เกิดอะไร |
|---|---|---|
| 1 สร้างงบประมาณ | ร่าง · ส่งกลับแก้ไข | กำลังกรอก / พิมพ์แบบฟอร์มให้ผู้อนุมัติเซ็น / แนบเอกสาร ยังไม่ส่ง |
| 2 อนุมัติ | **รออนุมัติ** | ส่งแล้ว — ผู้คุมงบตรวจมติ / เอกสารอนุมัติ → **ตรวจผ่าน (อนุมัติ)** หรือส่งกลับ (กลับไปขั้น 1) |
| 3 เปิดใช้ | ยังไม่เปิดใช้งบ · รอผู้คุมงบตรวจ Memo · ส่งกลับแก้ Memo | CAPEX: Business ทำ Memo ให้ผู้บริหารเซ็น แนบแล้วส่ง → ผู้คุมงบยืนยัน · OPEX ที่ Business สร้าง: ผู้คุมงบตรวจเอกสารอนุมัติแล้วเปิดใช้งบทันที (ไม่มีขั้นนี้) · OPEX ที่ผู้คุมงบลงไว้: Business กด "ขอดำเนินการใช้งบ" |
| จบ | **เปิดใช้งบ** | ขอเบิกใช้งบได้ ไม่มีขั้นตอนต่อ |

**ผู้คุมงบสร้างหรือ Import — 2 ขั้น: สร้างงบประมาณ → เปิดใช้** (ไม่มีร่างและไม่มีขั้นอนุมัติ — ผู้อนุมัติเซ็นไปแล้วก่อนผู้คุมงบนำมาใส่) · บันทึกแล้วสถานะ "ยังไม่เปิดใช้งบ" รอ Business เปิดใช้ (ขั้น 3 แบบเดียวกัน)

- แถบขั้นตอนใช้ชุดชื่อเดียวกันทั้งหน้าสร้างงบและหน้ารายละเอียดงบ · ยกเลิก = "ยกเลิก" ("งบนี้ถูกยกเลิกแล้ว") ไม่มีขั้นไหนถูกเลือก
- **ตัดสินแล้ว**: Memo ทำครั้งเดียวตอนขอเปิดใช้งบ (CAPEX) — หลังเปิดใช้งบแล้ว การเบิกใช้แต่ละครั้งไม่ต้องทำ Memo ผู้คุมงบตรวจและระบบคุมตามวงเงินที่เปิดใช้ · OPEX ไม่ต้องทำ Memo ตอนเปิดใช้
- **กฎ Items ก่อนเปิดใช้งบ**: ผู้คุมงบสร้างงบได้ทั้งแบบแยก Item และ "งบรวมทั้งโครงการ" · ถ้าเป็นงบรวม ตอน Business จะเปิดใช้งบต้อง **ลงรายละเอียด Item ให้ครบก่อน** (ผลรวมเท่ากับวงเงินรวมเดิม — หน้า "ลงรายละเอียด Item" `#/budget/:id/breakdown` ทำแทนได้โดยธุรการ) ถึงจะทำ Memo (CAPEX) / ขอดำเนินการใช้งบ (OPEX) ได้ · **Business และธุรการสร้างงบเองต้องแยก Item เสมอ** ไม่มีตัวเลือกงบรวม
- **เปิดใช้งบหลายตัวพร้อมกัน** (เฉพาะ Business เจ้าของงบ — ธุรการเปิดใช้งบไม่ได้): ที่แท็บ "งบรอขอดำเนินการใช้งบ" ในงานทั้งหมด ติ๊กเลือกงบ → **CAPEX** (อย่างน้อย 2 งบ บริษัทเดียวกัน) ทำ **Memo ใบเดียว** รวมทุกงบ (เลขที่ Memo เดียวกัน รายการ Item ของทุกงบอยู่ในเอกสารเดียว) แนบไฟล์ที่เซ็นแล้วและส่งที่งบหลัก ผู้คุมงบตรวจและยืนยันครั้งเดียว ทุกงบเปิดใช้พร้อมกัน (ส่งกลับ = กลับทั้งใบ · ยกเลิกการรวมได้ก่อนส่ง) · **OPEX** เลือกหลายงบแล้ว "ขอดำเนินการใช้งบที่เลือก" ครั้งเดียว (ไม่มี Memo) · CAPEX กับ OPEX แยกกัน

### 5.1 CAPEX — ผู้คุมงบลงงบให้ Business เปิดใช้ (ทางหลัก)

- **หน้าสร้างงบประมาณ** (ผู้คุมงบและ Business ใช้หน้าเดียวกัน · CAPEX / OPEX แบบเดียวกัน — OPEX ไม่มีช่องกลุ่ม Priority การลงทุน): แถบขั้นตอน 3 ขั้น → (1) ข้อมูลโครงการ: เลือก CAPEX / OPEX · Capex ID (รหัสโครงการ) · ชื่อโครงการ · บริษัท · หน่วยงานที่ขอ · กลุ่ม Priority · กลุ่ม Priority การลงทุน · เหตุผลสนับสนุน Priority · ปีที่ลงทุน · เจ้าของฝ่ายการเงิน (ช่องเลือก) · Owner (Business เจ้าของงบ — ผู้คุมงบเลือกได้, Business เป็นตัวเอง) → (2) โครงสร้างงบและรายการย่อย: แยกรายการย่อย (รหัส · ชื่อ · วงเงินรวม VAT) หรือ งบรวมทั้งโครงการ (มีแค่ช่องวงเงินรวม VAT) · ด้านขวา: สรุปคำขอ (มูลค่ารวม ประเภท ปี จำนวนรายการ สถานะ) และหมายเหตุ / ความจำเป็นของโครงการ · ปุ่ม "คัดลอกงบอื่น"
  - **สถานะต่างกันตามผู้สร้าง**: Business → "บันทึกแบบร่าง" (กรอกไม่ครบได้ — ต้องมีรหัสและชื่อ) หรือ "สร้างงบ" (ต้องครบ) แล้วรออนุมัติตามขั้นตอนเดิม (ร่างที่ยังไม่ครบส่งอนุมัติไม่ได้) · ผู้คุมงบ (หรือ Import) → "สร้างงบ" แล้วงบรอ Business ขอดำเนินการใช้งบอย่างเดียว (สร้างได้ทั้ง CAPEX และ OPEX)
  - **ตัวเลือกตั้งต้น** (แก้ / เพิ่มได้ที่ข้อมูลหลัก): หน่วยงานที่ขอ = FAC-PBI103, IT-WSW, PBI101, PBI103, PBI104 · กลุ่ม Priority = เพิ่มรายได้ (Revenue Growth), ลดรายจ่าย (Cost Efficiency), สร้างโอกาสอนาคต (Strategic/Future Growth) · กลุ่ม Priority การลงทุน = Digital AI Automation, Investment to Build the Future, Maintenance or Renovate, Platform to Ecosystem for BG, Production System Development for Demand Satisfaction
  - ช่องเลือกที่ข้อมูลหลักไม่มีตัวเลือกเลย ไม่บังคับ · กลุ่มรายการ / อ้างอิงการอนุมัติ / GL ไม่อยู่ในหน้านี้แล้ว (กลุ่มงบประมาณและประเภทสินทรัพย์ตัดออกจากระบบแล้ว) (ค่าเดิมจาก Import เก็บไว้ตามเดิม · GL ฝ่ายบัญชีใส่ที่หน้า GL)
1. **ผู้คุมงบลงงบประจำปี** ด้วยฟอร์ม หรือ **Import Excel** — **เลือกบริษัทที่จะนำเข้าก่อน แล้วจึงเลือกไฟล์** (ในไฟล์ไม่ต้องระบุบริษัท เพราะบัญชีแต่ละบริษัททำงบของบริษัทตัวเอง · ทุกงบในไฟล์เป็นบริษัทที่เลือก · เปลี่ยนบริษัทแล้วระบบตรวจไฟล์เดิมใหม่ให้) — (ก) ไฟล์ Capex / Opex Governance Framework ตรงๆ (หาแผ่นรายการจากหัวตาราง "Capex ID" / "Opex ID" ชื่อแผ่นอะไรก็ได้ ถ้าชื่อแผ่นขึ้นต้นด้วยรหัสบริษัทอื่นจะแจ้งเตือนในหน้าตรวจข้อมูล, ใช้แผ่น "สรุปโปรเจ็ค" อ่านกลุ่มรายการ, นำเข้าเฉพาะแถวสถานะ "อนุมัติแล้ว", CAPEX = งบรวมทั้งโครงการ, OPEX = งบรวมทั้งโครงการ, ชื่อ Owner ที่ไม่ตรงกับผู้ใช้เก็บเป็นข้อความ, บริษัท/หน่วยงาน/กลุ่มใหม่เพิ่มในข้อมูลหลักให้) หรือ (ข) ไฟล์ตัวอย่างรูปแบบรายการ Item (1 แถว = 1 Item, CAPEX เท่านั้น) · ตรวจข้อมูลก่อนนำเข้า งบที่ผิดไม่ถูกนำเข้า → สถานะ **"ยังไม่เปิดใช้งบ"**
2. ผู้คุมงบแก้ / ยกเลิกได้จนกว่า Business ส่ง Memo
3. **Business เจ้าของงบขอดำเนินการใช้งบครั้งแรก** (เปิดทั้งงบทีเดียว):
   กรอก **Memo ขอดำเนินการใช้งบ** (ฟอร์มตามโครงจริงของบริษัท มีเลขที่ `MEMO-ปี-ลำดับ`) → พิมพ์ให้ผู้บริหารเซ็นนอกระบบ → แนบไฟล์ที่เซ็นแล้ว → ส่ง → สถานะ "รอผู้คุมงบตรวจ Memo"
4. **ผู้คุมงบตรวจ Memo** → ยืนยัน = **"เปิดใช้งบ"** · หรือส่งกลับพร้อมเหตุผล (Business แก้ Memo แล้วส่งใหม่)

### 5.2 OPEX — Business สร้างเอง ผ่านการอนุมัติของผู้คุมงบ แล้วกดเปิดใช้

1. Business สร้างงบ OPEX (ร่าง) ใส่ Item หลักและวงเงินตามโครงการจริง
2. พิมพ์แบบฟอร์มของระบบ **หรือใช้เอกสารขออนุมัติของตนเอง** ส่งผู้อนุมัติเซ็นเองนอกระบบ
3. นำเอกสารอนุมัติที่เซ็นแล้วกลับมาแนบ + เลขที่เอกสาร + ชื่อผู้บริหาร → กด **"ส่งให้ผู้คุมงบตรวจสอบ"** (สถานะ **รออนุมัติ**) → ผู้คุมงบตรวจเอกสาร แล้วกด **"ตรวจผ่านและเปิดใช้งบ"** → งบ **"เปิดใช้งบ"** ทันที (ขั้นเดียว — **ไม่มี Memo และไม่มีขั้น Business กดขอดำเนินการใช้งบซ้ำ**) หรือส่งกลับให้แก้ (กลับไปขั้นสร้างงบ)
4. ผู้คุมงบสร้าง OPEX ด้วยฟอร์มหรือ **Import ไฟล์ Governance Framework (แผ่น Opex Request)** ได้ — งบที่นำเข้าเป็น OPEX แบบงบรวมทั้งโครงการ (ไม่มีรายละเอียด Item) อยู่สถานะ "ยังไม่เปิดใช้งบ" รอ Business เจ้าของงบกดขอดำเนินการใช้งบ (ผู้คุมงบเห็นงบ ปรับงบได้ตามปกติ)
5. **คัดลอกจากโครงการก่อนหน้า**: ตอนสร้างงบ OPEX ใหม่ Business เลือกโครงการ OPEX ของตนเป็นต้นแบบได้ (ปุ่ม "คัดลอก" บนฟอร์ม หรือ "คัดลอกเป็นโครงการใหม่" ในหน้างบ) — ดึงบริษัท หน่วยงาน กลุ่มงบ ชื่อ หมายเหตุ ปีงบ และ **Item หลักพร้อมวงเงิน / VAT / GL** มาใส่ฟอร์มให้แก้ต่อ · รหัสโครงการต้องกรอกใหม่ · ไม่คัดลอก Item ย่อย / เอกสารอนุมัติ / ไฟล์แนบ · ใช้ยอดปัจจุบันของโครงการเดิม (รวมที่ปรับแล้ว)
   - **ของบโดยยังไม่มีรายละเอียด Item ได้**: เลือกโครงสร้าง "งบรวมทั้งโครงการ" แล้วกรอกวงเงินรวม (เหมือน CAPEX) · ตอนขอเบิกแต่ละกลุ่มพิมพ์ชื่อรายการเอง (ไม่มีบริษัทที่ลงทุน / Memo) · ถ้าชื่อรายการตรงกับหมวดค่าใช้จ่ายในข้อมูลหลัก GL ของบรรทัดจะตั้งต้นตามหมวดนั้น · ไม่มีหน้า Item ย่อย / GL รายItem

### 5.3 CAPEX ที่ Business สร้างเอง

ร่าง → พิมพ์แบบฟอร์มเข้าที่ประชุม → แนบมติที่ประชุม + เลขที่มติ → ส่ง (**รออนุมัติ**) → ผู้คุมงบตรวจมติ **ผ่าน** หรือส่งกลับให้แก้ → ผ่านแล้วเข้าขั้น **เปิดใช้**: Business ทำ Memo ขอดำเนินการใช้งบให้ผู้บริหารเซ็น แนบแล้วส่ง → ผู้คุมงบยืนยัน = **"เปิดใช้งบ"** (เหมือน 5.1 ข้อ 3–4)

### 5.4 สถานะของงบ

ร่าง · **รออนุมัติ** · ส่งกลับแก้ไข · **ยังไม่เปิดใช้งบ** · รอผู้คุมงบตรวจ Memo · ส่งกลับแก้ Memo · **เปิดใช้งบ** · ยกเลิก
ขอเบิกใช้งบได้เฉพาะงบที่ **"เปิดใช้งบ"** และเฉพาะ Business เจ้าของงบ

## 6. เบิกใช้งบ (หลังงบเปิดใช้)

### 6.1 ขั้นตอน

1. **Business ขอเบิกใช้งบ** — 1 ใบเลือกได้หลาย Item (เลือกทีละบรรทัด) · ใส่วัตถุประสงค์ · เลือกประเภทการเบิก (ข้อ 6.2) · แนบเอกสารประกอบได้ · งบที่ไม่แยก Item เลือกหมวดค่าใช้จ่าย
2. ส่งตรงให้ผู้คุมงบตรวจ — **ไม่ต้องทำ Memo** (Memo ทำครั้งเดียวตอนขอเปิดใช้งบ) · ระบบเช็กวงเงินตามกฎข้อ 6.2
3. **ผู้คุมงบตรวจ** → **อนุมัติ** (ออกใบเบิกใช้งบ เลข `CAPEX-ปี-ลำดับ` หรือ `OPEX-ปี-ลำดับ`) หรือ **ส่งกลับ** (ต้องใส่เหตุผล; Business แก้แล้วส่งใหม่ หรือยกเลิก)
4. **ตัดงบและปิดยอด** ตามประเภท (ข้อ 6.2 — สำรองจ่าย / จ่ายตรง ตัดทันทีที่ผู้คุมงบอนุมัติ · เงินทดรอง Business / ธุรการเคลียร์ · PR/PO จัดซื้อบันทึก) → ปิดยอดแล้วคืนส่วนต่างเข้างบ

Business ยกเลิกได้เฉพาะตอนรอตรวจ / ถูกส่งกลับ — **ใบที่ออกแล้วยกเลิกไม่ได้**

### 6.1.1 ฟอร์มขอเบิก (CAPEX และ OPEX ใช้โครงเดียวกัน): จัดกลุ่มรายการ, Supplier รายบรรทัด และทำซ้ำรายการเบิก
- **กฎวงเงิน**: OPEX ขอเบิกเกินวงเงินของแต่ละ Item (งบรวมทั้งโครงการ = เกินวงเงินรวม) **ไม่ได้** — ปุ่มส่งกดไม่ได้ ต้องขอเพิ่มงบ / ให้ผู้คุมงบโยกงบก่อน · CAPEX เกินวงเงินรายการย่อยได้ (ผู้คุมงบใส่ Note) แต่ **ห้ามเกินยอดคงเหลือของงบรวมโครงการ**
- **ฟอร์มขอเบิก** มี 3 ขั้น: (1) ประเภทการเบิกใช้งบ (ใต้หัวข้อแสดงคำอธิบายของประเภทที่เลือก) (2) **ข้อมูลการดำเนินการ** (3) เงื่อนไขการจ่าย · ไม่มีช่อง "วัตถุประสงค์" และ "ผู้รับเงิน" ด้านบน (ทั้ง CAPEX และ OPEX)
- **กลุ่มรายการตามโครงสร้างงบ**: งบที่แยก Item (CAPEX / OPEX) → แต่ละกลุ่มเลือก **Item** (CAPEX เลือกได้เฉพาะรายการย่อยล่างสุด) · **งบรวมทั้งโครงการ** (ไม่มี Item) → แต่ละกลุ่ม**พิมพ์ชื่อรายการเอง** (ไม่ต้องเลือกหมวด) และ CAPEX เลือก **บริษัทที่ลงทุน** (มีข้อความบอกยอดคงเหลือของงบรวมเหนือกล่อง) — ถ้ากลุ่มใดใช้เงินข้ามบริษัทกับ PCC ปุ่มจะเปลี่ยนเป็น "ทำ Memo ให้ผู้บริหารเซ็นก่อนส่ง" · CAPEX ติ๊ก VAT 7% ไว้ให้ตั้งแต่แรก · **CAPEX มีช่อง "วัตถุประสงค์ของรายการนี้" ในแต่ละกลุ่ม** (**บังคับกรอก** — คำขอเดิมที่มีวัตถุประสงค์ระดับใบจะเติมให้ทุกกลุ่ม · เก็บในทุกบรรทัดของกลุ่ม และรวมเป็นวัตถุประสงค์ของคำขอ ใช้ในเอกสาร / Memo / Export)
- **ข้อมูลการดำเนินการ**: บนสุดมี **วันที่ส่งมอบ/วางบิล** และ **วันที่กำหนดจ่ายเงิน** (บังคับทั้งคู่ ตั้งต้นเป็นวันนี้) · ถัดมาเป็นกล่องรายการจัดกลุ่มตาม Item (กลุ่มติดกันในกล่องเดียว คั่นด้วยแถบบาง): แต่ละกลุ่มเลือก Item (แสดงยอดคงเหลือ) ปุ่มถังขยะลบทั้งกลุ่ม และมีตาราง No. · Supplier · รายละเอียด · จำนวนก่อน VAT · VAT 7% · รวม · × — ปุ่ม "+ เพิ่ม Supplier" เพิ่มบรรทัดในกลุ่ม (เช่น ค่าแรงคนงานหลายคน) · ปุ่ม "+ เพิ่มรายการใหม่" เพิ่มกลุ่ม Item ใหม่ · แถว "รวม" ท้ายกล่องรวมทุกกลุ่ม (ก่อน VAT · VAT · รวม) · ใต้กล่องเป็นแนบเอกสารประกอบ
- **Supplier**: ช่องเลือกจากข้อมูลหลัก (ข้อมูลหลัก > Supplier) · ชื่อใหม่เลือก "+ เพิ่มชื่อใหม่…" แล้วพิมพ์ชื่อ (เพิ่มเป็นตัวเลือกทันที และบันทึกเข้าข้อมูลหลักเมื่อส่งคำขอ · ชื่อเดิมที่ต่างช่องว่างใช้ตามข้อมูลหลัก) · บังคับทุกบรรทัดยกเว้นประเภท PR/PO · ผู้รับเงินของคำขอสรุปจาก Supplier (เกิน 3 ราย = "Supplier N ราย (ดูรายการ)") · แสดงเป็นคอลัมน์ในหน้าคำขอ เอกสารพิมพ์ และ Export
- **การ์ดสรุปคำขอเบิก** ด้านขวา: ยอดขอใช้ครั้งนี้ งบคงเหลือ คงเหลือหลังขอใช้ กล่องเตือนสิ่งที่ยังขาด (เหนือปุ่มส่ง) และการ์ดคำแนะนำในการเบิก · หัวหน้าแสดงสถานะ "แบบร่าง"
- **วันที่ส่งมอบ/วางบิล** และ **วันที่กำหนดจ่ายเงิน** แสดงในหน้าคำขอ เอกสารพิมพ์ และ Export (แผ่น "เบิกใช้งบ")
- **ทำซ้ำรายการเบิก (Duplicate)**: ปุ่ม "ทำซ้ำรายการเบิก" ในหน้าคำขอ (เฉพาะเจ้าของคำขอ งบต้องเปิดใช้) → เปิดฟอร์มขอเบิกที่คัดลอกประเภทการเบิก เงื่อนไขการจ่าย และทุกบรรทัด (รายการ / หมวด / Supplier / จำนวนเงิน / VAT) มาให้ เพิ่ม ลด แก้ได้ แล้วส่งเป็นคำขอใหม่ **ได้เลขที่คำขอใหม่** · ไม่คัดลอกไฟล์แนบและ Memo · คำขอเดิมไม่เปลี่ยน · ทำซ้ำได้ทุกสถานะ · คำขอ OPEX เก่าที่ยังไม่มี Supplier รายบรรทัด จะใช้ชื่อผู้รับเงินเดิมเป็น Supplier ของทุกบรรทัด

### 6.2 ประเภทการเบิก 4 แบบ และเงื่อนไขการตัดงบ

| ประเภท | ตัดงบเมื่อ | ใครบันทึก |
|---|---|---|
| ซื้อโดยเปิด PR / PO | จัดซื้อออก PO (ตามยอด PO) | จัดซื้อบันทึก PR/PO → ผู้คุมงบยืนยันยอดและปิดยอด |
| Advance (เงินทดรอง) | **Business / ธุรการ เคลียร์เงินทดรองพร้อมใบเสร็จ** (คล้าย PO — เบิกไปแล้วต้องกลับมาเคลียร์งบถึงถูกตัดจริง) | **ผู้คุมงบอนุมัติ = จ่ายเงินทดรอง** → Business / ธุรการกรอกยอดจริงตามใบเสร็จ + แนบไฟล์ → ตัดงบและปิดยอดอัตโนมัติ (ยอดต่างคืนเข้างบ) |
| พนักงานสำรองจ่าย | **ทันทีที่ผู้คุมงบตรวจผ่าน** (ยอดที่อนุมัติ) | ไม่ต้องมีใครบันทึกอีก — ระบบตัดงบและปิดยอดอัตโนมัติ |
| จ่ายตรงให้ Supplier | **ทันทีที่ผู้คุมงบตรวจผ่าน** (ยอดที่อนุมัติ) | ไม่ต้องมีใครบันทึกอีก — ระบบตัดงบและปิดยอดอัตโนมัติ |

- เฉพาะ **PR/PO** ที่ต้องรอ Role อื่น (จัดซื้อ) บันทึกก่อนถึงตัดงบ · เงินทดรองรอ Business / ธุรการ เคลียร์ · ประเภทอื่นตัดตอนผู้คุมงบอนุมัติเลย
- Business / ธุรการเห็นงาน **"รอเคลียร์เงินทดรอง"** ในงานทั้งหมด · ผู้คุมงบเคลียร์แทนไม่ได้
- คำขอที่อนุมัติไปก่อนเริ่มใช้กฎนี้ (ไม่มี `cutRule`) ยังจบด้วยขั้นตอนเดิม (ผู้คุมงบจ่ายทดรอง / เคลียร์ / บันทึกจ่าย) — ใบที่อนุมัติหลังจากนี้ใช้กฎใหม่
- PR/PO **จ่ายหลายงวดได้** แล้วค่อยปิดยอด · ยอดจริงมากกว่าที่ขอได้ ต้องใส่หมายเหตุ

### 6.3 ยอดคงเหลือและการจอง

- **จองไว้**: คำขอที่รอตรวจ และใบที่ออกแล้วแต่ยังไม่ตัดงบ (ยังหักออกจากคงเหลือ กันใช้ซ้ำ)
- **ตัดงบแล้ว**: ตามรายการตัดงบจริง · ใบที่มีหลาย Item แบ่งยอดตามสัดส่วนบรรทัด
- **เกินงบ Item แต่ไม่เกินงบโครงการ**: ขอได้ ระบบเตือน ผู้คุมงบต้องใส่ Note ตอนอนุมัติ (Note แสดงบนใบที่พิมพ์)
- **เกินงบทั้งโครงการ**: อนุมัติไม่ได้ จนกว่าผู้คุมงบโยกงบเข้า หรือส่งกลับให้ขอเพิ่มงบ

### 6.4 Memo ตอนเบิกใช้งบ

**ไม่มี** — Memo ทำครั้งเดียวตอนขอเปิดใช้งบ (CAPEX, ข้อ 5) · หลังเปิดใช้งบแล้ว ผู้คุมงบตรวจคำขอเบิกและระบบคุมตามวงเงินที่เปิดใช้ · คำขอเก่าที่ค้างสถานะ "รอแนบ Memo" ถูกเปลี่ยนเป็น "รอผู้คุมงบตรวจ" อัตโนมัติ (คำขอที่เคยแนบ Memo ไว้ยังเปิดดูได้)

## 7. การปรับงบ

| รายการ | ใครทำ | ขั้นตอน |
|---|---|---|
| **ขอเพิ่มงบ** (`INC-ปี-ลำดับ`) | Business เจ้าของงบ | ร่าง → ใส่เหตุผล + Item ที่ขอเพิ่ม (หรือ Item ใหม่ / วงเงินรวมถ้าเป็นงบรวมโครงการ) → แนบมติ (CAPEX) หรือเอกสารอนุมัติผู้บริหาร (OPEX) → ผู้คุมงบยืนยัน / ส่งกลับ |
| **โยกงบ** (`TRF-…`) | ผู้คุมงบ | ข้าม Item หรือข้ามโครงการได้ ต้องใส่เหตุผล · โยกไม่เกินคงเหลือของต้นทาง · ห้ามทำให้ต่ำกว่าที่จัดสรรให้ Item ย่อยแล้ว |
| **ลดงบ** (`DEC-…`) | ผู้คุมงบ | ต้องใส่เหตุผล ลดไม่เกินคงเหลือ |

ทุกครั้งที่ปรับ เก็บประวัติเป็น "ครั้งที่ / วันที่ / โดย / ยอดรวม" · ยังไม่มีแจ้งเตือนเจ้าของงบ (บันทึกในประวัติของงบทั้งสองฝั่ง) · ไม่มีงบกลาง / งบสำรอง

## 8. ฟีเจอร์เสริม

- **Item ย่อย OPEX**: Business เจ้าของงบหรือผู้คุมงบเพิ่มได้หลังงบเปิดใช้ ไม่ต้องอนุมัติซ้ำ (ยอดงบรวมไม่เปลี่ยน) · Item ที่มีการเบิกแล้วลบ / แก้รหัสไม่ได้
- **GL Code (OPEX)**: **บัญชี** (สิทธิ์ `gl.manage` ไม่ใช่ผู้คุมงบ) ใส่ที่เมนู "จัดการ GL" ได้ตั้งแต่ Business ส่งขอเปิดงบ OPEX (ไม่ต้องรอเปิดใช้งบ · งบที่ผู้คุมงบลงไว้ให้ใส่ได้เมื่อเปิดใช้แล้ว) และแก้ได้ทุกเมื่อหลังจากนั้น · ผู้คุมงบดู GL ได้แต่แก้ไม่ได้ · ใบเบิกที่ยังไม่มี GL แสดง GL ล่าสุดของ Item (รวมใน Excel) · หน้างบเตือน Item หลักที่ยังไม่มี GL
- **Plan Cashflow (CAPEX)**: Business เจ้าของงบหรือผู้คุมงบใส่ประมาณการรายเดือนของแต่ละ Item ตามเดือนของปีงบ (รวมไม่เกินวงเงิน Item) · แสดงเทียบกับยอดตัดงบจริง · แก้ได้ตลอด · **เป็นงานของ Business (ธุรการเห็นแทน)**: เมื่อถึงเดือนปัจจุบันของปีงบแล้วงบ CAPEX ที่เปิดใช้แล้วยังไม่มีแผนของเดือนนั้นเลย (ทุก Item เป็น 0) จะขึ้นงาน "วาง Plan Cashflow เดือนนี้" ในงานทั้งหมดและการ์ดงานที่ต้องทำ (หน้างบเตือนด้วย) · กด "วาง Plan Cashflow" หรือกด "เดือนนี้ไม่มีแผน" (บันทึกว่าเดือนนั้นไม่มีแผน — งานหายและไม่เตือนซ้ำของเดือนนั้น) · ผู้คุมงบไม่ได้รับงานนี้
- **ส่งออก Excel** (ผู้คุมงบ / Admin): 7 แผ่น — งบประมาณ, Item, เบิกใช้งบ, รายการในใบ, ตัดงบ-จ่ายเงิน, ปรับงบ, Plan Cashflow · กรองปี / บริษัท / ประเภท · ตัวเลขเป็นตัวเลขจริง
- **ช่องที่ต้องกรอก** มี `*` สีแดง และปุ่มจะกดไม่ได้จนกว่าจะครบ พร้อมบอกว่ายังขาดอะไร

## 9. เอกสารและเลขที่

- เลขที่ที่ระบบออกให้: `ตัวย่อ-ปี ค.ศ.-ลำดับ 4 หลัก` เริ่มนับใหม่ทุกปี — `REQ` คำขอ · `CAPEX` / `OPEX` ใบเบิกใช้งบ · `MEMO` · `INC` · `TRF` · `DEC`
- เลขที่ฝ่ายอื่นออก (รหัสโครงการ, Item No., PR, PO, เลขที่มติ, เลขใบเสร็จ) ผู้ใช้กรอกเอง
- เอกสารพิมพ์ / บันทึกเป็น PDF ได้: ใบเบิกใช้งบ (ผู้ขอ + ผู้ตรวจสอบเซ็น), Memo (หัวกระดาษโลโก้บริษัท), แบบฟอร์มขออนุมัติงบ — เป็นขาวดำ ขนาด A4

## 10. ข้อมูลหลัก (ผู้ดูแลแก้ที่เมนู "ข้อมูลหลัก")

บริษัท (รหัส ชื่อ โลโก้) · หน่วยงาน · Supplier · กลุ่มรายการ · กลุ่ม Priority · กลุ่ม Priority การลงทุน — ค่าที่ใช้อยู่แล้วลบไม่ได้

**ที่ตัดออกจากข้อมูลหลักแล้ว** (ไม่ต้องมีให้เพิ่ม): **ผู้ลงนาม Memo** — ผู้ทำ Memo กรอก เรียน / สำเนาถึง / ผู้ทบทวน / ผู้ลงนามเอง (เริ่มว่าง) · **GL Code** — ฝ่ายบัญชีมีหน้าจัดการ GL ของตัวเอง ที่นี่ผู้คุมงบกรอก GL Code และชื่อเป็นข้อความอิสระที่หน้า "ใส่ GL Code" ของแต่ละงบ OPEX · **หมวดค่าใช้จ่าย** — งบรวมโครงการกรอกรายการเป็นข้อความอิสระ ไม่เก็บเป็นหมวดหมู่ ฝ่ายบัญชีนำไป Map GL เอง (ข้อมูลหลักเดิมที่เคยบันทึกไว้จะถูกตัดออกเองตอนเปิดระบบ)

## 11. สิ่งที่ตัดออก / ยังไม่ทำ

- **ตัดออก**: DOA (ตาราง หมวดใน Item ช่องใน Memo) · บริษัทที่ลงทุนระดับ Item · เมนู "สิ่งที่รอยืนยัน"
- **ยังไม่ทำ**: ปิดปีงบ / ยกงบข้ามปี · แจ้งเตือน · บทบาท "ผู้บริหาร" ที่กดอนุมัติในระบบ · เชื่อมฐานข้อมูลจริง / ล็อกอินที่ปลอดภัยจริง · รูปแบบนำเข้าระบบบัญชีโดยเฉพาะ · เลขหน้าและแถบสีท้าย Memo

## จุดที่ควรทบทวน

**A. ที่ผมตัดสินใจเอง (ไม่ตรงก็บอกได้)**
1. **OPEX ของ Business ต้องผ่านผู้คุมงบตรวจ (อนุมัติ) ก่อนเปิดใช้** เหมือน CAPEX (แก้จากแบบเดิมที่เปิดใช้ทันที) · ขั้น "เปิดใช้" ของ OPEX ยังเป็นปุ่มเดียวของ Business ไม่มี Memo — รอตัดสินเรื่อง Memo (ข้อ 5.0)
2. **Business ยังขอตั้ง CAPEX เองได้** (ทางเดิมผ่านมติที่ประชุม) นอกจากทางที่ผู้คุมงบลงให้ — ถ้าไม่ต้องการ ตัดทางนี้ได้
3. **ช่องเลือกบริษัทที่ลงทุนรายบรรทัด** (เฉพาะงบรวมทั้งโครงการ) และมุมมอง "บริษัทที่ลงทุน" ในรายงานยังเหลือ — ตอนนี้ไม่มี Memo ข้ามบริษัทแล้ว ถ้าไม่มีการใช้เงินข้ามบริษัทเลย ตัดได้ทั้งชุด
4. ผู้คุมงบแก้งบที่ลงไว้ได้ **จนกว่า Business ส่ง Memo** เท่านั้น หลังจากนั้นต้องส่งกลับให้ Business แก้
5. ผู้คุมงบลดงบได้ **ไม่ต้องแนบเอกสารผู้บริหาร** (ใส่เหตุผลอย่างเดียว)
6. Admin ดูงบทุกงบแต่ไม่ทำรายการ
7. **ใบเบิกใช้งบที่ออกแล้ว ไม่มีใครยกเลิกได้** (ทั้งผู้ขอและผู้คุมงบ ไม่มีปุ่ม) — ถ้าเลือกงบหรือยอดผิด ต้องปิดยอดด้วยยอดจริงเพื่อคืนส่วนต่างเข้างบ

**B. ข้อความเก่าในหน้า "สิ่งที่รอยืนยัน" (`#/assumptions`) ที่ไม่ตรงกับระบบปัจจุบัน** (หน้านี้ถูกซ่อนจากเมนูแล้ว)
- "ขั้นตอน Memo … MEMO-บริษัทปี-ลำดับ" → ตอนนี้เป็น `MEMO-ปี-ลำดับ`
- "ใครเลือกว่าทำ Memo … / เงื่อนไขการทำ Memo ตอนเบิกใช้" → เลิกแล้ว (Memo ทำครั้งเดียวตอนขอเปิดใช้งบ)
- ถ้าจะใช้หน้านี้อ้างอิงต่อ ผมควรแก้ให้ตรงก่อน

**C. คำถามเรื่องงานจริงที่ยังเปิดอยู่**
1. ปุ่ม **"คัดลอกจากโครงการก่อนหน้า"** (OPEX) ทำแล้ว — ขอบเขตที่คัดลอกตามข้อ 5.2 ข้อ 5 ตรงกับที่ต้องการหรือไม่ (เช่น อยากให้คัดลอก Item ย่อยด้วยไหม, ปีงบ / ชื่อควรเว้นว่างให้กรอกใหม่ไหม)
2. ผู้บริหารจะกดอนุมัติในระบบเองในอนาคตหรือไม่ (ตอนนี้เซ็นนอกระบบแล้วแนบไฟล์)
3. ปิดปีงบ: งบเหลือหมดสิทธิ์หรือยกไปปีถัดไป
4. ต้องการแจ้งเตือน (อีเมล / LINE) เมื่อมีงานรอหรือถูกส่งกลับหรือไม่
5. ฝ่ายบัญชีต้องการคอลัมน์ / รูปแบบ Excel เพิ่มเติมหรือไม่
6. เมื่อเปลี่ยนไปใช้ฐานข้อมูลจริง: ผู้ใช้ล็อกอินด้วยอะไร และใครกำหนดบทบาท
7. **ค้างรอเจ้าของระบบตัดสิน — ใครกดตรวจ / ยืนยันแทนผู้คุมงบได้**: เลือกว่าให้กดได้เฉพาะ **ผู้รับผิดชอบงบนั้น** หรือ **ทุกคนในบริษัทที่บัญชีมีสิทธิ์** (ตอนนี้เป็นแบบหลัง คือทุกคนในบริษัทที่มีสิทธิ์กดได้) — ยังไม่เปลี่ยนจนกว่าเจ้าของระบบจะตอบ

**D. ชุดทดสอบโหมดทดลองเดิม — 4 รายการที่ตกอยู่ก่อนหน้า (ยังไม่แก้)**
- แจ้งโดยเจ้าของระบบ: `menu` 1 รายการ · `nodoa` 1 รายการ · `opexproj` 2 รายการ (เรื่อง GL ตั้งต้นของ OPEX แบบงบรวมทั้งโครงการหลังตัดหมวดค่าใช้จ่ายออก)
- ตกอยู่ก่อนงานเปลี่ยนชื่อรีโป / เลขเวอร์ชัน 2026.11.18-1 (รอบนั้นแก้แค่เอกสารกับเลขเวอร์ชัน)
- ไฟล์ชุดทดสอบนี้ไม่ได้อยู่ในรีโป (ในรีโปมีแค่ `supabase/tests/` ของเฟส 1–3) จึงยังไม่ได้รันซ้ำหรือยืนยันสาเหตุของ `menu` กับ `nodoa` — ต้องรันชุดเดิมแล้วดูผลก่อนแก้ (อย่าปรับเงื่อนไขทดสอบให้ผ่านโดยไม่ตรวจว่าพฤติกรรมของระบบถูกต้อง)

## 12. ล็อกอินและบัญชีผู้ใช้ (โหมดทดลอง)

**ขั้นตอน** (ระบบจริงใช้ขั้นตอนเดียวกัน โดยเปลี่ยนไปใช้ Supabase Auth)
1. เข้าสู่ระบบด้วย **อีเมล + รหัสผ่าน**
2. **Admin เป็นคนเพิ่มอีเมล** (พร้อมชื่อ ตำแหน่ง หน่วยงาน บริษัท บทบาท) — สถานะเริ่มต้น "รอตั้งรหัสผ่าน" · **ผู้ใช้ตั้งรหัสผ่านเอง** ที่หน้าล็อกอิน → "ตั้งรหัสผ่าน" (Admin ไม่เห็น / ไม่ตั้งให้)
3. **ลืมรหัสผ่าน**: ผู้ใช้กด "ลืมรหัสผ่าน" เพื่อแจ้ง Admin (บัญชีจะขึ้นสถานะ "ขอรีเซ็ตรหัสผ่าน") → Admin กด "รีเซ็ตรหัสผ่าน" (ล้างรหัสเดิม) → ผู้ใช้เข้า "ตั้งรหัสผ่าน" แล้วกรอกรหัสใหม่เอง
4. ผู้ใช้เปลี่ยนรหัสผ่านเองได้ที่เมนูมุมขวาบน → "บัญชีของฉัน"

**ข้อมูลบัญชี**: `email` (ไม่ซ้ำ ไม่สนตัวพิมพ์) · `name` · `title` ตำแหน่ง · `department` หน่วยงาน · `company` บริษัท · `role` · `active` — ใช้แยกงานและให้เลือกชื่อเพื่อแท็กงานถึงคนได้ (`userOptions()` / `userLabel()` ใน `js/app.js` ให้ผู้ใช้ที่เปิดใช้งานพร้อมตำแหน่ง/หน่วยงาน/บริษัท)

**กติการหัสผ่าน**: อย่างน้อย 8 ตัว มีทั้งตัวอักษรและตัวเลข ไม่ซ้ำอีเมล · เก็บเป็น hash (PBKDF2-SHA256 + salt) · ใส่ผิดติดกัน 5 ครั้งพัก 30 วินาที · บัญชีที่ถูกปิดการใช้งานล็อกอินไม่ได้และหลุดจากระบบทันที · ตั้งรหัสผ่านเองได้เฉพาะบัญชีที่ "รอตั้งรหัสผ่าน" (กันคนอื่นแย่งตั้ง)

**ขอบเขตบริษัทที่ดูได้ (`companies`)**: ผู้คุมงบและจัดซื้อ (ผู้ที่เห็นงบทั้งหมดได้) เห็นเฉพาะงบ / คำขอเบิก / คำขอเพิ่มงบ / เอกสารของ **บริษัทที่บัญชีมีสิทธิ์** (ได้หลายบริษัท) — เห็น **ทุกงานของบริษัทนั้นแม้ไม่ใช่ผู้รับผิดชอบ (เจ้าของฝ่ายการเงิน)** · ใช้กับรายการงบ รายการเบิก งานที่ต้องทำ รายงาน ส่งออก Excel Import งบ ช่องเลือกบริษัทตอนสร้างงบ รายการโยก/ลดงบ และลิงก์ตรง (เปิดแล้วขึ้น "ไม่มีสิทธิ์ดูข้อมูลของบริษัท …") · `companies` ว่าง = ไม่เห็นงบเลย (Admin ตั้งให้) · Admin เห็นทุกบริษัท · Business เห็นเฉพาะงบของตนเหมือนเดิม · บัญชีใหม่ที่ Admin เพิ่มมีค่าตั้งต้น = บริษัทของบัญชีนั้น · บัญชีที่ไม่มีฟิลด์นี้ (โหมด Supabase ที่ฐานข้อมูลคุมสิทธิ์) ไม่จำกัด
**สิทธิ์ในการกด (action)**: ตอนนี้ผู้คุมงบทุกคนที่มีสิทธิ์ในบริษัทนั้นตรวจ / ยืนยัน / ส่งกลับได้ (ไม่ต้องเป็นผู้รับผิดชอบ) และ Log ผู้ทำจริงเสมอ — **ยังรอเจ้าของระบบตัดสิน** ว่าจะให้กดได้เฉพาะผู้รับผิดชอบหรือไม่

**ข้อจำกัดของโหมดทดลอง**: บัญชีเก็บใน `localStorage` (`procurement.v5.users`) ใครแก้ในเบราว์เซอร์ได้ก็ข้ามได้ — **ไม่ปลอดภัยจริง** ใช้ทดสอบขั้นตอนเท่านั้น · ปุ่ม "เข้าด้วยบัญชีตัวอย่าง (ข้ามรหัสผ่าน)" **ปิดอยู่แล้ว** (`DEMO_QUICK_LOGIN = false` ตั้งเป็น true เพื่อเปิดกลับมาทดสอบ) — ตอนเริ่ม Admin เข้าครั้งแรกโดยหน้าล็อกอิน → "ตั้งรหัสผ่าน" ด้วยอีเมลบัญชีตัวอย่าง `adisorn@demo.test` แล้วเพิ่มอีเมลจริงของตนเป็น Admin ที่หน้า Admin · "ล้างข้อมูลทดสอบ" ไม่ลบบัญชี · บริษัทของบัญชียังไม่ถูกใช้จำกัดการมองเห็นงบ

**ฟังก์ชันสำหรับหน้า Admin** (`window.AppAccounts` — ตรวจสิทธิ์ `user.manage` เอง): `list()` · `create({email,name,title,department,company,companies,role})` · `update(id, fields)` (รับ `companies` ได้) · `setActive(id, bool)` · `resetPassword(id)` · `state(u)` → `pending | ok | reset_requested | inactive`

**หน้าผู้ดูแลระบบ (โหมดทดลอง)**: เมนู "ผู้ใช้" — ตาราง + ค้นหา/กรองบทบาท/สถานะ · เพิ่ม/แก้ผู้ใช้ (หน่วยงานและบริษัทเลือกจากข้อมูลหลัก · ติ๊ก "บริษัทที่ดูงบ / งานได้" หลายบริษัท — ผู้คุมงบ/จัดซื้อต้องเลือกอย่างน้อย 1) · เปิด/ปิดใช้งาน (ปิดตัวเองไม่ได้) · รีเซ็ตรหัสผ่าน (มี confirm) · แถบเตือนบัญชีที่ขอรีเซ็ต · เมนู "บทบาทและสิทธิ์" — เลือกบทบาททางซ้าย แล้วติ๊กสิทธิ์ของบทบาทนั้นทางขวา (ปุ่มบันทึก/ยกเลิกเปิดเมื่อมีการแก้ · เตือนก่อนเปลี่ยนบทบาทถ้ายังไม่บันทึก) · สร้างบทบาท (คัดลอกสิทธิ์จากบทบาทอื่นได้) / แก้ชื่อ / ลบ ผ่าน Modal · คืนค่าเริ่มต้น (`window.AppRoles`) · เมนู "ข้อมูลหลัก" / "Log การทำงาน" เปิดหน้าเดิม (ไม่มีแถบแท็บในหน้า — ทุกหมวดอยู่ที่เมนูซ้าย)

**โหมดล็อกอินจริงบน Supabase (เฟส 1 บัญชี · เฟส 2 ข้อมูลหลัก — เปิดเองเมื่อใส่ `supabaseAnonKey` ใน `js/config.js`)** · ตั้งค่าตาม `supabase/SETUP-v2.md`
- บัญชี บทบาท และสิทธิ์อยู่ใน Supabase (`supabase/schema_v2.sql` ตาราง `v2_roles` / `v2_profiles` · เข้าผ่านฟังก์ชัน `v2_*` ที่ตรวจสิทธิ์ที่ฐานข้อมูล · RLS เปิดและไม่มี policy) · ล็อกอินด้วย Supabase Auth (อีเมล + รหัสผ่าน)
- ไม่มีลิงก์ ไม่ส่งอีเมล: Admin เพิ่มอีเมลผู้ใช้ (หน้าต่าง Modal) → ผู้ใช้เข้าหน้าล็อกอิน กด **"เปิดใช้ครั้งแรก"** กรอกอีเมลตัวเอง → ระบบตรวจว่า Admin เพิ่มแล้วหรือยัง (`v2_activation_status`) → ถ้าเพิ่มแล้วและยังไม่เคยตั้งรหัสผ่านก็ตั้งรหัสผ่านเองได้ (Edge Function `v2-admin-users` action `activate` ที่ถือ service_role ฝั่งเซิร์ฟเวอร์ ตรวจซ้ำและจองสิทธิ์แบบอะตอมมิก ตั้งซ้ำทับไม่ได้) · "ลืมรหัสผ่าน" = แจ้ง Admin (`v2_request_reset`) → Admin "รีเซ็ตรหัสผ่าน" (ล้างรหัสเดิม) → ผู้ใช้ "เปิดใช้ครั้งแรก" ตั้งใหม่ · **ข้อควรระวัง**: ใครรู้อีเมลที่ Admin เพิ่มไว้และเปิดใช้ก่อนเจ้าของอีเมลจะยึดบัญชีได้ และระบบบอกได้ว่าอีเมลไหนมีอยู่ — Admin เห็นสถานะ "รอตั้งรหัสผ่าน" และรีเซ็ตได้
- **1 ผู้ใช้หลายบทบาท**: `v2_profiles.roles` (รายการ) — สิทธิ์ = รวมทุกบทบาท (`_v2_perms(text[])`) · `role` = บทบาทหลัก (roles[1]) ซิงก์ด้วย trigger เพื่อให้ SQL/Edge Function เก่าใช้ต่อได้ · ฟังก์ชันที่เบราว์เซอร์เรียก `v2_update_user(..., p_roles text[])` (แบบ `p_role` เดิมยังเรียกได้) · หน้าเว็บ: ฟอร์มผู้ใช้ติ๊กบทบาทหลายอัน (ใช้ `.chip`) ตารางแสดงทุกบทบาท ตัวกรองบทบาทตรงกับบทบาทใดก็ได้ · ตรวจที่ฐานข้อมูล: Admin คนสุดท้าย (นับสิทธิ์รวม) · ลบบทบาทที่ยังมีผู้ใช้มีอยู่ไม่ได้
- **บริษัท / หน่วยงาน / ใครมีอะไร**: หน่วยงานอยู่ใต้บริษัท (ข้อมูลหลัก `departments[{name, company}]`) · Business: `company` 1 + `departments` 1 (งบขึ้นเป็นหน่วยงานของเจ้าของงบ · บริษัทของงบเลือกได้อิสระ ไม่ผูกกับหน่วยงาน) · ธุรการ: `departments` ได้หลายหน่วยงาน + `companies` (บริษัทที่รับผิดชอบ) + `proxyFor` · ผู้คุมงบ/บัญชี/จัดซื้อ: `companies` เท่านั้น · ธุรการสร้างงบไม่ได้และเห็น/ทำแทนเฉพาะงบที่เปิดใช้แล้ว · ตรวจที่ `v2_save_docs` (หน่วยงานของงบ ∈ หน่วยงานของเจ้าของ · ธุรการ: ห้ามสร้างงบ / ห้ามแตะงบที่ยังไม่เปิดใช้ / คำขอเบิก-เพิ่มงบเฉพาะงบที่เปิดใช้แล้ว) · ฟอร์มผู้ใช้แสดงช่องตามสิทธิ์ของบทบาท (`userNeeds()` ใน js/app.js)
- อีเมลของบัญชีแก้ไม่ได้ · ปิดบัญชี = ban ใน Supabase Auth · ระบบกันไม่ให้ปิด/ลดสิทธิ์ Admin คนสุดท้าย · รายชื่อสำหรับเลือก/แท็กงาน (`v2_directory`) ไม่มีอีเมล
- **ข้อมูลหลัก (เฟส 2) เก็บบนเซิร์ฟเวอร์** (`v2_master` · 6 รายการ: บริษัท หน่วยงาน กลุ่มรายการ Supplier กลุ่ม Priority กลุ่ม Priority การลงทุน) — ทุกคนเห็นชุดเดียวกัน · อ่านได้ทุกคนที่ล็อกอิน · แก้ได้เฉพาะผู้มีสิทธิ์จัดการข้อมูลหลัก · Admin ที่เข้าระบบคนแรกบันทึกค่าปัจจุบันขึ้นเป็นต้นฉบับ · กันบันทึกทับกัน (ใช้เวลาอัปเดตล่าสุดตรวจ) · ผู้ขอเพิ่มชื่อ Supplier ใหม่ได้ผ่านฟอร์มขอเบิก (เพิ่มอย่างเดียว) · เก็บประวัติทุกครั้งที่บันทึก · โหลดไม่ได้ → ใช้ค่าในเครื่องต่อแต่บันทึกข้อมูลหลักไม่ได้
- **งบ คำขอเบิก คำขอเพิ่มงบ และ Log (เฟส 3) เก็บบนเซิร์ฟเวอร์** (`supabase/schema_v2b.sql` ตาราง `v2_docs` / `v2_counters` / `v2_log` · ฟังก์ชัน `v2_load` / `v2_save_docs`) — เก็บเป็นเอกสารรายตัว (งบ 1 ใบ = 1 แถว) พร้อมเลขเวอร์ชันกันแก้ทับ · **การมองเห็น**: Business เห็นเฉพาะงบที่ตนเป็นเจ้าของและคำขอที่ตนเป็นผู้ขอ · ผู้คุมงบ/จัดซื้อเห็นเฉพาะบริษัทใน `companies` ของบัญชี · Admin เห็นทุกบริษัท · **การเขียน**: ตรวจสิทธิ์ตามชนิดเอกสาร + ต้องเป็นเอกสารที่ผู้เขียนมองเห็น (ก่อนและหลังแก้) · คอลัมน์บริษัท/เจ้าของคำนวณที่เซิร์ฟเวอร์ ปลอมจากเบราว์เซอร์ไม่ได้ · **เลขที่เอกสารออกโดยเซิร์ฟเวอร์** (ตัวนับรายคำนำหน้า-ปี ไม่ซ้ำ ไม่มีช่องว่าง: เว็บใส่ token `@@NO:REQ-2026:xxxx@@` เซิร์ฟเวอร์แทนที่ทั้งเอกสารและ Log ในธุรกรรมเดียว) · เว็บบันทึกเฉพาะเอกสารที่เปลี่ยน (เทียบ snapshot) หน่วงสั้นๆ แล้วส่งเป็นชุดเดียว · ชนกัน (CONFLICT) = โหลดข้อมูลล่าสุดและแจ้งเตือน · ออฟไลน์ = ลองใหม่ทุก 8 วินาที · โหลดเพิ่มเติมทุก 30 วินาที / เมื่อกลับมาที่แท็บ · ยังไม่ตรวจกฎขั้นตอนที่เซิร์ฟเวอร์ (ใครอนุมัติได้ ยอดไม่เกินวงเงิน) · ไฟล์แนบยังฝังในเอกสาร · เริ่มฐานข้อมูลว่าง ไม่นำข้อมูลทดลองในเบราว์เซอร์ขึ้น · ปุ่มล้างข้อมูลทดสอบ/โหลดตัวอย่างปิดในโหมดนี้
