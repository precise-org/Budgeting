# ตั้งค่า Supabase — เฟส 1: ล็อกอินและบัญชีผู้ใช้จริง · เฟส 2: ข้อมูลหลัก

ใช้กับระบบรอบใหม่ (ตารางขึ้นต้น `v2_` ไม่แตะตารางของระบบรอบแรก) · ทำครั้งเดียว ประมาณ 20 นาที
เฟส 1 ย้าย **ล็อกอิน บัญชี บทบาทและสิทธิ์** · เฟส 2 ย้าย **ข้อมูลหลัก** (บริษัท หน่วยงาน กลุ่มรายการ Supplier กลุ่ม Priority กลุ่ม Priority การลงทุน) ไปไว้บนเซิร์ฟเวอร์ · เฟส 3 ย้าย **งบ คำขอเบิกใช้งบ คำขอเพิ่มงบ และ Log การทำงาน** (ข้อมูลที่ผู้ใช้ส่งงานถึงกัน) ไปไว้บนเซิร์ฟเวอร์

## 1. ตั้งค่าการล็อกอิน (Authentication)
**Authentication → Sign In / Providers → Email**
- เปิด Email provider
- **ปิด** "Allow new users to sign up" (ให้ผู้ดูแลเพิ่มผู้ใช้เท่านั้น)

> ระบบนี้ **ไม่ใช้ลิงก์และไม่ส่งอีเมล** (ไม่ต้องตั้ง SMTP / URL Configuration) — Admin เพิ่มอีเมลของผู้ใช้ แล้วผู้ใช้เข้าหน้าล็อกอิน กด "เปิดใช้ครั้งแรก" กรอกอีเมลตัวเอง ระบบตรวจว่า Admin เพิ่มแล้วหรือยัง ถ้าเพิ่มแล้วและยังไม่เคยตั้งรหัสผ่านก็ตั้งรหัสผ่านของตัวเองได้เลย

## 2. สร้างตารางและฟังก์ชัน
**SQL Editor → New query (tab ว่าง)** → วางเนื้อหา [`schema_v2_all.sql`](schema_v2_all.sql) **ทั้งไฟล์** (ไฟล์เดียว รวม `schema_v2.sql` + `schema_v2b.sql` แล้ว) → **Run**
- รันซ้ำได้ ไม่ลบข้อมูล · **ทุกครั้งที่อัปเดตเว็บแล้วมีแถบเตือน "ฐานข้อมูลยังไม่อัปเดต" ให้รันไฟล์นี้ใหม่** (ผู้พัฒนาจะแจ้งในสรุปทุกครั้งว่ารอบนี้ต้องรันหรือไม่)
- วางแล้วตรวจจำนวนบรรทัดของไฟล์ให้ตรงกับต้นฉบับก่อนกด Run (ถ้า tab เดิมมีข้อความเก่าค้างอยู่ จะขึ้น error `syntax error at or near "$$"`) — ใช้ New query หรือ Ctrl+A ลบของเก่าก่อน
- (ไฟล์ `schema_v2.sql` และ `schema_v2b.sql` ยังอยู่ ใช้แก้ไข/อ่านเทียบได้ — `schema_v2_all.sql` สร้างจากสองไฟล์นี้ด้วย `supabase/build_schema_all.sh`)

> **กฎธุรกิจที่ฐานข้อมูลบังคับ (สคีมาเวอร์ชัน 6 — รัน `schema_v2_all.sql` ซ้ำ)**: นอกจากสิทธิ์/บริษัท/หน่วยงาน ฐานข้อมูลตรวจตอนบันทึกทุกครั้ง (`_v2_check_doc`) — ใครเรียก API ตรงก็ข้ามไม่ได้
> - **งบ:** สร้างใหม่ได้เฉพาะร่าง/ส่งอนุมัติ (Business) หรือรอเปิดใช้ที่ผู้คุมงบลงไว้ · ผู้คุมงบเท่านั้นที่ตรวจผ่าน/ส่งกลับ (CAPEX → รอเปิดใช้ · OPEX → เปิดใช้เลย) · CAPEX เปิดใช้ได้ต้องส่ง Memo (เจ้าของงบ) แล้วผู้คุมงบยืนยัน ข้ามไม่ได้ · OPEX ที่ผู้คุมงบลงไว้ เจ้าของงบกดเปิดเอง · งบที่ส่งตรวจแล้วแก้รายการ/วงเงินไม่ได้ · งบที่เปิดใช้แล้วเปลี่ยนวงเงินได้เฉพาะปรับงบ/ขอเพิ่มงบที่ยืนยัน · GL แก้ได้เฉพาะบัญชี (ระหว่างงบรออนุมัติก็ใส่ได้) · ลบงบที่เปิดใช้/อยู่ระหว่างตรวจไม่ได้
> - **คำขอเบิก:** ขอได้เฉพาะงบที่เปิดใช้ โดยเจ้าของงบหรือธุรการของหน่วยงาน (ในนามเจ้าของงบ) · อนุมัติ/ส่งกลับเฉพาะผู้มีสิทธิ์ตรวจ · ใบที่ออกเอกสารแล้วแก้ยอด/รายการไม่ได้ · การตัดงบแก้/ลบไม่ได้ · PO เฉพาะจัดซื้อ · เงินทดรอง = อนุมัติคือจ่ายทดรอง แล้ว Business/ธุรการเป็นคนเคลียร์ · สำรองจ่าย/จ่ายตรง ตัดงบและปิดยอดอัตโนมัติตอนอนุมัติ · ใบเก่าก่อนกฎตัดงบใหม่ (ไม่มี cutRule) ใช้ขั้นตอนเดิม
> - **คำขอเพิ่มงบ:** ขอได้เฉพาะงบที่เปิดใช้ · ผู้คุมงบเท่านั้นที่ยืนยัน/ส่งกลับ · ที่ยืนยันแล้วแก้ไม่ได้
> - **สวิตช์ปิดฉุกเฉิน** (ถ้ากฎเข้มเกินจนบล็อกงานที่ถูกต้อง — ใช้ชั่วคราวแล้วแจ้งผู้พัฒนา): `update public.v2_settings set value = 'off' where key = 'enforce_rules';` เปิดกลับ: `'on'` · ผู้ใช้ที่ถูกบล็อกจะเห็นข้อความภาษาไทยบอกเหตุ (เช่น "เปลี่ยนสถานะงบ … ไม่ถูกขั้นตอน")

## 3. สร้างผู้ดูแลระบบคนแรก
1. **Authentication → Users → Add user → Create new user** ใส่อีเมลจริง + รหัสผ่านที่คุณตั้งเอง (ติ๊ก **Auto Confirm User**)
2. กลับ SQL Editor แล้วรัน (แก้อีเมลและชื่อ):
   ```sql
   insert into public.v2_profiles (id, email, name, title, role)
   select id, email, 'ชื่อ นามสกุล', 'ตำแหน่ง', 'admin'
   from auth.users where lower(email) = lower('อีเมลที่สร้างไว้');
   ```
คนถัดไปให้ Admin เพิ่มในหน้า Admin (ไม่ต้องเข้า dashboard อีก)

## 4. ติดตั้ง Edge Function `v2-admin-users`
ฟังก์ชันนี้ถือ service_role ฝั่งเซิร์ฟเวอร์ ใช้สร้างบัญชี / รีเซ็ตรหัสผ่าน / ปิดบัญชี / ตั้งรหัสผ่านครั้งแรกของผู้ใช้ (เบราว์เซอร์ห้ามถือ service_role key) — **ถ้าเคย Deploy ไว้แล้ว ให้วางโค้ดใหม่ทับแล้ว Deploy อีกครั้ง**

ผ่าน dashboard: **Edge Functions → Deploy a new function** → ตั้งชื่อ `v2-admin-users` → วางโค้ดจาก [`functions/v2-admin-users/index.ts`](functions/v2-admin-users/index.ts) → Deploy
หรือผ่าน CLI: `supabase functions deploy v2-admin-users --project-ref <project-ref>`

`SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` Supabase ใส่ให้ฟังก์ชันเอง ไม่ต้องตั้ง secret เพิ่ม (secret `SITE_URL` ที่เคยตั้งไว้ไม่ใช้แล้ว ลบทิ้งได้)

## 5. เชื่อมเว็บกับโปรเจกต์
**Project Settings → API** คัดลอก **anon public key** ใส่ที่ `js/config.js` ช่อง `supabaseAnonKey` (ค่านี้เปิดเผยในหน้าเว็บได้ — **ห้ามใส่ service_role key**) แล้วขึ้นเว็บตามขั้นตอนใน `CLAUDE.md`
พอมี anon key ระบบจะเปลี่ยนจากโหมดทดลองเป็นล็อกอินจริงอัตโนมัติ (บัญชีตัวอย่างและ `DEMO_QUICK_LOGIN` ไม่ใช้อีกต่อไป)

## เฟส 2: ข้อมูลหลักบนเซิร์ฟเวอร์
หลังรัน `schema_v2_all.sql` (ขั้นตอน 2) ไม่ต้องตั้งค่าอะไรเพิ่ม:
- **ครั้งแรก**: เมื่อผู้ใช้ที่มีสิทธิ์ "จัดการข้อมูลหลัก" (Admin) เข้าระบบ ระบบบันทึกข้อมูลหลักที่เห็นอยู่ในเบราว์เซอร์นั้น (ค่าตั้งต้น + ที่เคยแก้) ขึ้นเซิร์ฟเวอร์เป็นต้นฉบับ (เฉพาะรายการที่เซิร์ฟเวอร์ยังไม่มี) — **ถ้าเบราว์เซอร์นั้นมีข้อมูลทดสอบปนอยู่ ให้เข้าเมนู ข้อมูลหลัก แก้ให้ถูกต้องก่อนแจ้งผู้ใช้อื่น**
- หลังจากนั้นทุกคนเห็นชุดเดียวกัน: Admin แก้ที่เมนู ข้อมูลหลัก → ผู้ใช้อื่นเห็นเมื่อเข้าระบบ / กลับมาที่แท็บ / โหลดหน้าใหม่
- Admin สองคนแก้รายการเดียวกันพร้อมกัน: คนที่บันทึกทีหลังด้วยค่าเก่าจะถูกปฏิเสธและเห็นค่าล่าสุด (ไม่ทับกัน)
- ผู้ขอเบิกพิมพ์ชื่อ Supplier ใหม่ในฟอร์มขอเบิก → เพิ่มเข้าข้อมูลหลักกลางให้เอง (เพิ่มได้อย่างเดียว)
- ทุกครั้งที่บันทึกเก็บสำเนาไว้ในตาราง `v2_master_history` (อ่านได้ที่ SQL Editor เท่านั้น ไว้ตรวจย้อนหลัง / กู้ค่าเดิม)
- ถ้าหน้าข้อมูลหลักขึ้นว่า "เชื่อมข้อมูลหลักกับเซิร์ฟเวอร์ไม่ได้" แปลว่ายังไม่ได้รัน `schema_v2.sql` เวอร์ชันล่าสุด หรืออินเทอร์เน็ตขัดข้อง — ระบบยังใช้งานต่อได้ด้วยค่าในเครื่อง แต่บันทึกข้อมูลหลักไม่ได้จนกว่าจะเชื่อมต่อได้

## เฟส 3: งบ คำขอเบิก คำขอเพิ่มงบ และ Log บนเซิร์ฟเวอร์
หลังรัน `schema_v2_all.sql` (ขั้นตอน 2) ไม่ต้องตั้งค่าอะไรเพิ่ม:
- ผู้ใช้ทุกคนเห็นข้อมูลงบชุดเดียวกัน **ตามสิทธิ์และบริษัท**: Business เห็นเฉพาะงบที่ตนเป็นเจ้าของและคำขอที่ตนเป็นผู้ขอ · ผู้คุมงบ/จัดซื้อ เห็นทุกงบของ "บริษัทที่ดูงบ/งานได้" ของบัญชี · Admin เห็นทุกบริษัท (กติกาตรวจที่ฐานข้อมูล ไม่ใช่แค่ซ่อนที่หน้าเว็บ)
- เว็บบันทึกเฉพาะเอกสารที่เปลี่ยนไปเซิร์ฟเวอร์เองหลังกดบันทึก (มีแถบ "กำลังบันทึก…" มุมขวาล่าง) และโหลดสิ่งที่คนอื่นทำทุก 30 วินาที / เมื่อกลับมาที่แท็บ · ปิดหน้าตอนยังบันทึกไม่เสร็จเบราว์เซอร์จะเตือน
- **เลขที่เอกสาร (REQ / INC / MEMO / TRF / DEC / CAPEX / OPEX …) ออกโดยเซิร์ฟเวอร์** ไม่ซ้ำ ไม่มีช่องว่าง — เห็นเลขจริงทันทีที่บันทึกเสร็จ (ช่วงสั้นๆ ก่อนหน้านั้นเป็นเลขชั่วคราว)
- สองคนแก้เอกสารเดียวกันพร้อมกัน: คนที่บันทึกทีหลังด้วยข้อมูลเก่าจะเห็นแถบ "มีผู้อื่นแก้ข้อมูลเดียวกันไปก่อน" ระบบโหลดข้อมูลล่าสุดให้ และของผู้อื่นไม่ถูกเขียนทับ (การแก้ไขที่ยังไม่ได้บันทึกของเรื่องนั้นต้องทำซ้ำ)
- ออฟไลน์: ระบบลองบันทึกใหม่ทุก 8 วินาทีจนกว่าจะสำเร็จ (อย่าปิดหน้า) · ปุ่ม "ล้างข้อมูลทดสอบ / โหลดข้อมูลตัวอย่าง" ในเมนูผู้ใช้ปิดอยู่ในโหมดนี้ (ข้อมูลเป็นของกลาง)
- เริ่มด้วยฐานข้อมูลว่าง — ข้อมูลทดลองที่เคยอยู่ในเบราว์เซอร์ไม่ถูกนำขึ้น
- **ข้อจำกัด (ช่วงนี้)**: ฐานข้อมูลตรวจ "ใครแก้เอกสารไหนได้" (สิทธิ์ตามบทบาท + บริษัท + เจ้าของ) และกันบันทึกทับกัน แต่ **ยังไม่ตรวจกฎขั้นตอน** (เช่น ใครกดอนุมัติได้ ยอดไม่เกินวงเงิน ขั้นตอนต้องเรียงตามลำดับ) — ยังตรวจที่เบราว์เซอร์ ผู้ที่ล็อกอินแล้วและรู้วิธีเรียก API ตรงๆ อาจข้ามกฎขั้นตอนได้ในขอบเขตสิทธิ์ของตน เหมาะกับการทดสอบกับผู้ใช้จริงกลุ่มเล็กที่ไว้ใจกัน (จะย้ายกฎสำคัญมาตรวจที่เซิร์ฟเวอร์ในเฟสถัดไป) · ไฟล์แนบยังฝังในเอกสาร (ไม่เกิน 400 KB ต่อไฟล์ เอกสารละไม่เกิน 8 MB) — จะย้ายไป Storage ภายหลัง
- ถ้าเว็บขึ้น "เปิดระบบไม่สำเร็จ" หลังล็อกอิน แปลว่ายังไม่ได้รัน `schema_v2b.sql` หรืออินเทอร์เน็ตขัดข้อง


## 1 ผู้ใช้หลายบทบาท
Admin → ผู้ใช้ → แก้ไข/เพิ่มผู้ใช้ ติ๊กบทบาทได้หลายอัน — **สิทธิ์ของผู้ใช้ = รวมสิทธิ์ของทุกบทบาท** (บทบาทแรกตามลำดับในรายการเป็น "บทบาทหลัก" ไว้แสดงผล) · กฎมองเห็นงบ/เอกสาร ขอบเขตบริษัท การกัน Admin คนสุดท้าย และการลบบทบาท (ลบไม่ได้ถ้ายังมีผู้ใช้มีบทบาทนั้นอยู่) นับทุกบทบาท
- **อัปเกรดจากเวอร์ชันเก่า**: รัน `schema_v2_all.sql` ใหม่ (เพิ่มคอลัมน์ `v2_profiles.roles` และย้ายค่า `role` เดิมให้เอง) และ **Deploy Edge Function `v2-admin-users` ใหม่** (ให้เพิ่มผู้ใช้พร้อมหลายบทบาทได้) — ต้องทำทั้งสามอย่างก่อนใช้เว็บเวอร์ชันนี้
- สร้างผู้ดูแลระบบคนแรกด้วย SQL (ขั้นตอน 3) ยังใช้แบบเดิมได้ (ใส่แค่ `role`) · แก้คอลัมน์ `role` ตรงๆ ใน SQL Editor = ตั้งเป็นบทบาทเดียว

## บริษัท หน่วยงาน และสิ่งที่ผู้ใช้แต่ละประเภทต้องมี
- **ข้อมูลหลัก → บริษัทและหน่วยงาน** (หน้าเดียว): หน่วยงานเป็นบรรทัดย่อยใต้บริษัท เพิ่ม/ลบได้ทั้งสองระดับ · ชื่อหน่วยงานไม่ซ้ำกันทั้งระบบ · รหัสบริษัทแก้ไม่ได้หลังสร้าง (ข้อมูลอื่นอ้างด้วยรหัส — ผิดให้ลบแล้วสร้างใหม่ถ้ายังไม่ถูกใช้) · ลบบริษัทที่ยังมีหน่วยงานหรือถูกใช้ในงบไม่ได้ · หน่วยงานเดิมที่ยังไม่มีบริษัท (เช่นที่ระบบเติมจากงบเดิม) จะอยู่ท้ายตารางให้เลือกบริษัทให้ครบก่อนบันทึก · เปลี่ยนชื่อ/ลบหน่วยงานที่ยังมีผู้ใช้สังกัดอยู่ไม่ได้
- **Business**: มี "บริษัทสังกัด" 1 บริษัท + "หน่วยงาน" 1 หน่วยงาน (เลือกได้เฉพาะหน่วยงานใต้บริษัทนั้น) · ตอนขอใช้งบเลือกบริษัทของงบเป็นบริษัทอื่นได้ แต่งบจะขึ้นเป็น **หน่วยงานของเจ้าของงบ** เสมอ (ฐานข้อมูลตรวจ: หน่วยงานของงบต้องอยู่ในหน่วยงานของเจ้าของงบ — ตรวจเมื่อสร้างงบหรือเปลี่ยนหน่วยงาน/เจ้าของ)
- **ธุรการ (Admin ผู้ช่วย Business)**: Admin เลือก "หน่วยงานที่ช่วยงาน" ได้หลายหน่วยงาน (แสดงแยกตามบริษัทของหน่วยงาน — ไม่มีการเลือกชื่อ Business แล้ว) · เห็นและทำแทนได้เฉพาะงบของหน่วยงานเหล่านั้นที่ **เปิดใช้งานแล้ว** ไม่ว่าบริษัทของงบจะเป็นบริษัทไหน (คำขอเบิก/ขอเพิ่มงบก็เช่นกัน · ฐานข้อมูลบังคับ) · **สร้างงบไม่ได้** · ธุรการที่ยังไม่ได้กำหนดหน่วยงานจะไม่เห็นงบของใครเลย · เอาสิทธิ์ "ขออนุมัติงบใหม่" ออกจากบทบาทธุรการตั้งต้นให้อัตโนมัติ (เฉพาะที่ยังไม่ได้ปรับสิทธิ์เอง)
- **ผู้คุมงบ / บัญชี / จัดซื้อ**: ไม่มีหน่วยงานประจำ มีแต่ "บริษัทที่รับผิดชอบ" (เลือกได้หลายบริษัท) — งานของบริษัทเหล่านั้นเท่านั้น
- หน้า Admin → ผู้ใช้: ฟอร์มแสดงช่องตามบทบาทที่ติ๊ก (Business = สังกัด · ธุรการ = หลายหน่วยงาน · ผู้ทำงาน = บริษัทที่รับผิดชอบ) · เปลี่ยนชื่อหน่วยงานที่ยังมีผู้ใช้สังกัดอยู่ไม่ได้
- **อัปเกรด**: รัน `schema_v2_all.sql` ใหม่ (เพิ่มคอลัมน์ `v2_profiles.departments` / `v2_docs.department` และย้ายค่าเดิมให้เอง · ฟังก์ชัน `v2_update_user` รวมเหลือเวอร์ชันเดียวที่รับหลายหน่วยงาน) และ **Deploy Edge Function `v2-admin-users` ใหม่**

## ใช้งานจริง
| ต้องการ | ทำที่ |
|---|---|
| เพิ่มผู้ใช้ | Admin → ผู้ใช้ → + เพิ่มผู้ใช้ (หน้าต่าง Modal) ใส่อีเมล/ชื่อ/บทบาท → แจ้งผู้ใช้ → ผู้ใช้เข้าหน้าล็อกอิน กด "เปิดใช้ครั้งแรก" กรอกอีเมลตัวเอง แล้วตั้งรหัสผ่านเอง |
| ผู้ใช้ลืมรหัสผ่าน | ผู้ใช้กด "ลืมรหัสผ่าน" (บัญชีขึ้น "ขอรีเซ็ตรหัสผ่าน" + ตัวเลขที่เมนู Admin) → Admin กด "รีเซ็ตรหัสผ่าน" (ล้างรหัสเดิม) → ผู้ใช้กด "เปิดใช้ครั้งแรก" ตั้งรหัสใหม่เอง |
| ปิดบัญชี | Admin → ผู้ใช้ → ปิดใช้งาน (ล็อกอินไม่ได้ทันที ระบบกันไม่ให้ปิด Admin คนสุดท้าย) |
| แก้สิทธิ์ / ชื่อบทบาท / สร้างบทบาท | Admin → บทบาทและสิทธิ์ (แก้ชื่อที่หัวคอลัมน์) |
| ให้ผู้ใช้มีหลายบทบาท | Admin → ผู้ใช้ → แก้ไข → ติ๊กบทบาทหลายอัน |

## ความปลอดภัย (สิ่งที่ระบบทำให้ / สิ่งที่ต้องระวัง)
- ตาราง `v2_*` เปิด RLS และไม่มี policy — เบราว์เซอร์อ่าน/เขียนตารางตรงๆ ไม่ได้ ทุกอย่างผ่านฟังก์ชัน `v2_*` ที่ตรวจสิทธิ์ฝั่งฐานข้อมูล · รายชื่อผู้ใช้สำหรับเลือก/แท็กงาน (`v2_directory`) ไม่มีอีเมล
- Admin ไม่เห็นและไม่ตั้งรหัสผ่านให้ผู้ใช้ — รหัสผ่านที่ระบบสร้างตอนเพิ่ม/รีเซ็ตเป็นค่าสุ่มที่ไม่มีใครรู้
- **ข้อควรระวังของวิธี "เปิดใช้ครั้งแรกด้วยอีเมล"**: ใครรู้อีเมลที่ Admin เพิ่มไว้และเปิดใช้ **ก่อนเจ้าของอีเมล** จะตั้งรหัสผ่านและยึดบัญชีนั้นได้ (ไม่มีลิงก์/รหัสยืนยันเฉพาะตัว) และระบบบอกได้ว่าอีเมลไหนมีอยู่ในระบบ — แจ้งผู้ใช้ให้เปิดใช้ทันทีหลังเพิ่มบัญชี · Admin เห็นสถานะ "รอตั้งรหัสผ่าน" และกด "รีเซ็ตรหัสผ่าน" เพื่อล้างบัญชีที่ถูกยึดได้ · ถ้าต้องการให้เข้มกว่านี้ (เช่น ต้องมีรหัสเปิดใช้ที่ Admin ให้) บอกได้
- **Log การทำงานเก็บบนเซิร์ฟเวอร์** (เพิ่มอย่างเดียว ผู้ทำ = ผู้ล็อกอินเสมอ ไม่เชื่อค่าจากเบราว์เซอร์): ผู้มีสิทธิ์ดู Log เห็นทั้งหมด ผู้อื่นเห็นเฉพาะที่ตนทำ/ที่ทำกับงบของตน · ขอบเขตบริษัท (`companies`) ถูกบังคับที่ฐานข้อมูลแล้ว (เฟส 3) · **ข้อมูลหลักอ่านได้ทุกคนที่ล็อกอิน** (เป็นข้อมูลตัวเลือก ไม่ใช่ข้อมูลลับ) แก้ได้เฉพาะผู้มีสิทธิ์จัดการข้อมูลหลัก (ตรวจที่ฐานข้อมูล) · การเช็ก "ลบได้ไหม / เปลี่ยนชื่อ" ในหน้าข้อมูลหลักดูเฉพาะงบที่ผู้ใช้คนนั้นเห็น (ไม่ใช่งบทั้งระบบ)

## ทดสอบฐานข้อมูล (ไม่จำเป็นสำหรับผู้ใช้)
ดู `tests/v2_test.sql` และ `tests/v2b_test.sql` (ฐานข้อมูล: สิทธิ์ การมองเห็น เวอร์ชัน การออกเลข) และ `tests/web_master.js` (หน้าเว็บจริง ↔ Supabase จำลอง ↔ Postgres) — รันกับ Postgres ในเครื่องพร้อม `tests/shim.sql`:
```bash
psql -v ON_ERROR_STOP=1 -d sp -f tests/shim.sql -f schema_v2.sql -f schema_v2b.sql -f tests/v2_test.sql
# ฐานข้อมูลใหม่อีกฐานสำหรับ v2b_test.sql: ... -f schema_v2.sql -f schema_v2b.sql -f tests/v2b_test.sql
```
PGDATABASE=sp node web_master.js   # ในโฟลเดอร์ tests (ต้อง npm install และมี Playwright) ทดสอบเฟส 2 ทั้งระบบ
