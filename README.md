# Budgeting — ระบบขอเบิกใช้งบประมาณ

## ต้นแบบเวอร์ชันใหม่ (v2) — หน้าหลัก `index.html`

ต้นแบบสำหรับให้ผู้ใช้งานลองเล่นและเสนอ Function เพิ่ม (โหมดทดลอง ข้อมูลเก็บในเบราว์เซอร์ ไม่ต่อ Supabase)
เวอร์ชันเดิมยังเปิดได้ที่ `v1/` (เก็บข้อมูลแยกกัน) — เนื้อหาด้านล่างหัวข้อ "ระบบขอเบิกใช้งบประมาณ (ต้นแบบ)" อธิบายเวอร์ชันเดิม

| บทบาท (สลับที่เมนูมุมขวาบน) | ทำอะไรได้ |
| --- | --- |
| Business (สมชาย / สุดา) | สร้างร่างคำขออนุมัติงบ (แยกรายการย่อย หรือ งบรวมโครงการ) → พิมพ์แบบฟอร์มเข้าที่ประชุม → แนบมติแล้วส่งให้ผู้คุมงบ, ขอเบิกใช้งบ (เฉพาะงบที่ตนสร้าง), ขอเพิ่มงบ |
| ผู้คุมงบ | เห็นเฉพาะงบของบริษัทที่บัญชีมีสิทธิ์ (หลายบริษัทได้) แต่เห็นทุกงานของบริษัทนั้น · ลงงบประจำปี (สร้าง / Import Excel), ตรวจ Memo ขอดำเนินการใช้งบ CAPEX, ยืนยัน/ส่งกลับงบและคำขอเพิ่มงบ, ตรวจคำขอเบิกใช้งบ (ขอเกินงบรายการต้องใส่ Note), บันทึกจ่ายเงินทดรอง / เคลียร์ / จ่ายคืนพนักงาน / จ่าย Supplier และปิดยอด, โยกงบ (ข้ามโครงการได้) / ลดงบ |
| จัดซื้อ | บันทึก PR / PO ของใบเบิกใช้งบประเภท PR/PO (ตัดงบตามยอด PO) |
| บัญชี (นิดา) | ใส่ / แก้ GL Code ของงบ OPEX ที่เมนู "จัดการ GL" หลังผู้คุมงบยืนยัน Item และงบเปิดใช้แล้ว · ดูงบ / ส่งออก Excel · ไม่ใช่ผู้คุมงบ |
| Admin ผู้ช่วย Business (พิมพ์ — ธุรการ) | ทำเอกสารแทน Business ได้ทุกอย่างในบริษัทที่มีสิทธิ์ (ถ้า Admin แท็ก "ช่วยงานให้ Business" ในหน้าผู้ใช้ จะเฉพาะ Business ที่แท็ก · ยังไม่แท็กใครเลย = ทั้งบริษัทไปก่อน) ยกเว้น **เปิดใช้งบครั้งแรก** (ต้องเป็น Business เจ้าของงบ) |
| Admin (อดิศร) | ข้อมูลหลัก, Log การทำงานทั้งระบบ, ผู้ใช้และสิทธิ์ (โหมดทดลองดูได้อย่างเดียว) |

- งานที่ต้องทำของแต่ละบทบาทรวมอยู่ที่เมนู **งานทั้งหมด** แยกเป็นแท็บ (ตัวเลขสีแดง = งานที่ต้องลงมือ)
- ผู้ใช้ทั่วไปดู **ประวัติการทำรายการ** ของตน (รวมสิ่งที่ผู้อื่นทำกับงบ/เอกสารของตน) — Log ทั้งระบบเห็นเฉพาะ Admin

- ประเภทการเบิกใช้งบ (CAPEX): ซื้อโดยเปิด PR/PO (ตัดงบเมื่อออก PO), Advance (ตัดเมื่อเคลียร์), พนักงานสำรองจ่าย (ตัดเมื่อจ่ายคืน), จ่ายตรงให้ Supplier (ตัดเมื่อจ่าย)
- ยอดจริงต่างจากที่ขอ → ปิดยอดแล้วคืนส่วนต่างเข้างบ
- ทุกการกระทำเก็บประวัติในเอกสาร และรวมไว้ที่หน้า "Log การทำงาน"
- เมนูหลักเรียงจากบนลงล่าง: **งบประมาณ** (หน้าแรก · รายการแบบตาราง ค้นหา / กรอง / เรียงคอลัมน์ / แบ่งหน้า 50 งบต่อหน้า พร้อมยอดรวมของงบที่เปิดใช้งบตามตัวกรอง) → งานทั้งหมด → รายการเบิกใช้งบ → ประวัติการทำรายการ → (ข้อมูลหลัก / ส่งออกข้อมูล / Log / ผู้ใช้และสิทธิ์ ตามสิทธิ์) → **รายงาน** (เดิมคือ "ภาพรวม") · เมนู "สิ่งที่รอยืนยัน" นำออกจากเมนูแล้ว (หน้ายังเปิดได้ที่ `#/assumptions`)
- **OPEX (เดิมชื่อ CBS) ในต้นแบบ v2** ใช้ขั้นตอนเดียวกับ CAPEX ทุกอย่าง (ขอเบิกใช้งบ 4 ประเภท → ผู้คุมงบตรวจสอบ → ตัดงบ → ปิดยอด) ต่างกันที่การอนุมัติงบ: **ไม่เข้าบอร์ด แต่ให้ผู้บริหารอนุมัติ** — Business แนบเอกสารอนุมัติ + เลขที่ + ชื่อผู้บริหาร แล้วผู้คุมงบตรวจสอบและยืนยัน (เพิ่มงบก็เช่นเดียวกัน) ส่วนหัวข้อ "กระบวนการขอเบิกใช้งบโครงการ (CBS)" ด้านล่างอธิบายเวอร์ชันเดิม (`v1/`)

## ระบบขอเบิกใช้งบประมาณ (ต้นแบบ)

เปิดใช้งบได้ที่ `index.html` (รองรับ GitHub Pages โดยไม่ต้องมี backend) — หน้าทดสอบเดิมย้ายไปที่ `test.html`

> ระบบนี้ **ไม่ใช่การขออนุมัติงบ** — งบได้รับอนุมัติมาแล้ว ระบบใช้ **ตรวจสอบ (verify) ว่าใช้ถูกตัวงบ**
> และให้ผู้ใช้งบรู้ว่างบของตนเหลือเท่าไร

ใช้เมนู **"เข้าใช้งานในฐานะ"** มุมขวาบนเพื่อสลับผู้ใช้ตัวอย่างตามบทบาท

| บทบาท | ทำอะไรได้ |
| --- | --- |
| ฝ่ายการเงิน | บันทึก/ปรับงบที่อนุมัติแล้ว (เก็บประวัติการปรับทุกครั้ง), รับเอกสาร CAPEX แล้ว *อนุมัติ* หรือ *ไม่อนุมัติ (แจ้งเหตุผล)*, บันทึก *งวดจ่าย* (วันส่งมอบ/วางบิล, วันกำหนดจ่าย, ยอดงวด) |
| ผู้ขอซื้อ / ผู้ขอใช้งบ | ดูยอดงบของตนเอง (*งบที่ได้รับ / ใช้แล้ว / รอตรวจสอบ / คงเหลือ*) ลงลึกถึงรายการย่อย และจัดทำเอกสารขอเบิกใช้งบทุกครั้งที่จะใช้ |
| ฝ่ายบัญชี | บันทึกข้อมูลบัญชีของเอกสารที่ออกแล้ว: CAPEX แยก Asset / Expenses *รายงวด*, CBS ยืนยัน GL Code *รายบรรทัด* และสถานะจ่าย |

### รายงาน (Dashboard) และข้อมูลหลัก
- **รายงาน** (เมนูสุดท้าย เดิมชื่อ "ภาพรวม") (ทุกบทบาท; ผู้ขอเห็นเฉพาะงบของตนเอง): กรองตามปี / บริษัท / ประเภทงบ แสดงงบที่ได้รับ ตัดงบแล้ว จองไว้ คงเหลือ
  ตารางสรุปตามบริษัท / กลุ่มงบ / หน่วยงาน / ประเภทงบ, กราฟตัดงบรายเดือน (นับเฉพาะที่บัญชีบันทึกจ่ายแล้ว),
  รายการงานที่ต้องทำตามบทบาท และงบที่เกินหรือเหลือน้อยกว่า 10%
- **ข้อมูลหลัก** (การเงิน): บริษัท, หน่วยงาน, กลุ่มรายการ, กลุ่ม Priority, กลุ่ม Priority การลงทุน, Supplier — ใช้เป็นตัวเลือกในฟอร์มตั้งงบ (เลือก GL Code แล้วเติมชื่อ GL ให้)
  ลบค่าที่ถูกใช้อยู่ไม่ได้, รหัสแก้ไม่ได้หลังสร้าง, เปลี่ยนชื่อหน่วยงาน/ประเภทสินทรัพย์ ระบบแก้ให้ทุกงบ
  มีรายชื่อผู้ใช้/บทบาทให้ดู (อ่านอย่างเดียว)

### โครงสร้างงบ (ตามไฟล์ Excel เดิม)
- **CAPEX**: บริษัท, ปีงบ, *รหัสโครงการ (Project No.)* → *รายการย่อย (Item No.)* แต่ละรายการมีวงเงินรวม VAT
- **Memo ทำครั้งเดียวตอนขอเปิดใช้งบ**: งบ CAPEX ทำ Memo ให้ผู้บริหารเซ็นตอน "ขอดำเนินการใช้งบ" (OPEX ไม่ต้องทำ) · หลังเปิดใช้งบแล้ว การเบิกใช้แต่ละครั้งส่งตรงให้ผู้คุมงบตรวจ ไม่ต้องทำ Memo — ระบบคุมตามวงเงินที่เปิดใช้ (OPEX เกินวงเงินต่อ Item / งบรวมไม่ได้ · CAPEX เกินรายการได้แต่ห้ามเกินงบรวม)
- **กฎเปิดใช้งบ (ล่าสุด)**: Business / ธุรการสร้างงบเองต้องแยก Item เสมอ · งบรวมทั้งโครงการที่ผู้คุมงบลงไว้ ต้องให้ Business ลงรายละเอียด Item ให้ครบก่อนถึงจะทำ Memo / ขอเปิดใช้งบได้ · OPEX ที่ Business สร้าง ผู้คุมงบตรวจเอกสารอนุมัติแล้วเปิดใช้งบทันที (ไม่มี Memo) · เปิดใช้หลายงบพร้อมกันได้ที่แท็บ "งบรอขอดำเนินการใช้งบ" — CAPEX รวม Memo ใบเดียว (บริษัทเดียวกัน) · OPEX เปิดใช้ครั้งเดียวหลายงบ
- **กฎตัดงบ (ล่าสุด)**: เฉพาะ PR/PO ที่รอจัดซื้อบันทึก PO · เงินทดรอง — ผู้คุมงบอนุมัติ = จ่ายเงินทดรอง แล้ว Business / ธุรการต้องเคลียร์ตามใบเสร็จงบถึงถูกตัดจริง · พนักงานสำรองจ่าย / จ่ายตรง Supplier — ตัดงบและปิดยอดทันทีที่ผู้คุมงบตรวจผ่าน (ไม่ต้องมี Role อื่นบันทึกอีก)
- **Plan Cashflow เป็นงานของ Business**: งบ CAPEX ที่เปิดใช้แล้ว เมื่อถึงเดือนปัจจุบันแล้วยังไม่มีแผนใช้เงินของเดือนนั้น ขึ้นงาน "วาง Plan Cashflow เดือนนี้" ให้ Business เจ้าของงบ (ธุรการเห็นแทน) — วางแผน หรือกด "เดือนนี้ไม่มีแผน"
- **ขั้นตอนหลักของงบ (CAPEX / OPEX เหมือนกัน)**: Business สร้าง = สร้างงบประมาณ (ร่าง) → อนุมัติ (สถานะ "รออนุมัติ" — ผู้อนุมัติเซ็นนอกระบบ ผู้คุมงบกดตรวจผ่าน / ส่งกลับ) → เปิดใช้ (CAPEX ส่ง Memo ให้ผู้คุมงบยืนยัน · OPEX กดขอดำเนินการใช้งบ) · ผู้คุมงบสร้าง / Import = สร้างงบประมาณ → เปิดใช้ · แถบขั้นตอนใช้ชุดเดียวกันทั้งระบบ · **กฎวงเงินเบิก**: OPEX เกินวงเงินต่อ Item / งบรวมไม่ได้ · CAPEX เกินรายการย่อยได้แต่ห้ามเกินงบรวม
- **Journey งบประจำปี**: **CAPEX** — ผู้คุมงบลงงบของแต่ละปีให้ Business ด้วย "ลงงบประจำปี" (ฟอร์ม) หรือ "Import Excel" (ดาวน์โหลดไฟล์ตัวอย่าง → กรอก 1 แถวต่อ 1 Item → เลือกไฟล์ .xlsx / .csv → ตรวจข้อมูล → นำเข้า) งบอยู่สถานะ **ยังไม่เปิดใช้งบ** → Business เจ้าของงบเปิดใช้ครั้งแรก (เปิดทั้งงบทีเดียว) โดยทำ Memo ขอดำเนินการใช้งบ (กรอกตามโครง Memo ของบริษัท) → พิมพ์ให้ผู้บริหารเซ็น → แนบไฟล์ที่เซ็นแล้ว → ส่ง → ผู้คุมงบตรวจ Memo แล้วยืนยันเปิดใช้ (หรือส่งกลับให้แก้) · ผู้คุมงบแก้ / ยกเลิกงบที่ลงไว้ได้จนกว่า Business ส่ง Memo · **OPEX** — Business เป็นผู้สร้างงบเอง (ผู้คุมงบลง / Import OPEX ไม่ได้): สร้างร่าง → พิมพ์แบบฟอร์มของระบบ หรือใช้เอกสารขออนุมัติของตนเอง ส่งผู้บริหารอนุมัติเองนอกระบบ → นำเอกสารอนุมัติกลับมาแนบ + เลขที่เอกสาร + ชื่อผู้บริหาร → กด "ขอดำเนินการใช้งบ" งบเปิดใช้ทันที ไม่ผ่านผู้คุมงบยืนยัน · Business ขอตั้ง CAPEX ใหม่เองได้ (ร่าง → แนบมติที่ประชุม → ผู้คุมงบยืนยันเปิดใช้)
- **หน้างบประมาณ (หน้าแรก)**: ชื่อหน้า + ปุ่ม "สร้างงบประมาณ" + "Import งบ" (ผู้คุมงบ) / "ขออนุมัติงบใหม่" ชิดขวา → การ์ดตัวเลข 4 ใบ (จำนวนงบ · งบที่ได้รับอนุมัติ · ตัดงบ+จองไว้ · คงเหลือ — เปลี่ยนตามตัวกรอง) → แผง "ตารางทะเบียนงบประมาณ" (งบที่ยังไม่เปิดใช้งบแสดง "คงเหลือ" เท่ากับวงเงินทั้งหมด เพราะยังไม่มีการใช้ · ตัดงบ / จองไว้แสดง –) (จำนวนรายการ, ตัวกรองปี / บริษัท / ค้นหา / หน่วยงาน / ประเภท / สถานะ, หัวคอลัมน์กดเรียง, แบ่งหน้า 50 งบ)
- **สไตล์ UI**: ใช้ภาษาออกแบบตาม [`docs/STYLE.md`](docs/STYLE.md) (Sarabun / Kanit / IBM Plex Mono, ธีมสว่าง, token สีใน `css/style.css`) เป็นหลักจนกว่าเจ้าของระบบจะสั่งเปลี่ยน
- **DOA (อำนาจอนุมัติ)**: ไม่อยู่ในระบบ — ตรวจสอบกันเองแบบ Manual: CAPEX ผู้คุมงบนำงบที่ผ่านการอนุมัติแล้วมาลงในระบบให้ Business เปิดใช้ · OPEX Business ส่งผู้อนุมัติตามที่ตนรู้เซ็นเอง แล้วแนบเอกสารเปิดใช้งบ (ระบบบันทึกข้อมูลทุกครั้งที่ขอใช้) · ไม่มีหมวด DOA ในรายการ Item, ไม่มีตาราง DOA ในใบเบิกใช้งบ และไม่มีช่อง "อ้างอิงอำนาจอนุมัติ" ใน Memo · ข้อมูลหมวด DOA ที่เคยบันทึกไว้ในข้อมูลเก่าไม่ถูกนำมาแสดง
- **คำเรียกในระบบ**: จังหวะเปิดใช้งบครั้งแรก (Business กดเริ่มใช้งบ / ทำ Memo ให้ผู้บริหารเซ็น) ใช้คำว่า **"ขอดำเนินการใช้งบ"** · เมื่องบเปิดใช้งบแล้ว การขอใช้เงินแต่ละครั้งใช้คำว่า **"เบิกใช้งบ"** (ปุ่ม "เบิกใช้งบ", เมนู "รายการเบิกใช้งบ", ใบเบิกใช้งบ)
- **ข้อมูลสำหรับทดสอบ**: เว็บเริ่มต้นแบบว่าง (ไม่มีงบ / คำขอ) แต่มีข้อมูลหลักครบ · เมนูมุมขวาบนมี "ล้างข้อมูลทั้งหมด (เริ่มทดสอบ)" และ "โหลดข้อมูลตัวอย่าง" · ถ้าต้องการล้างข้อมูลในทุกเบราว์เซอร์อีกครั้ง ให้เปลี่ยนค่า `DATA_EPOCH` ใน `js/app.js`
- **หน้าสร้างงบประมาณ** ผู้คุมงบและ Business ใช้หน้าเดียวกัน (CAPEX / OPEX แบบเดียวกัน · OPEX ไม่มีกลุ่ม Priority การลงทุน): ข้อมูลโครงการตามไฟล์ Governance · โครงสร้างงบ (แยกรายการย่อย / งบรวมทั้งโครงการ = มีแค่วงเงินรวม VAT) · สรุปคำขอด้านขวา · คัดลอกงบอื่น · Business มี "บันทึกแบบร่าง" และ "สร้างงบ" (รออนุมัติ) · ผู้คุมงบ "สร้างงบ" แล้วรอ Business ขอดำเนินการใช้งบ · ฟอร์มขอเบิก CAPEX มีวัตถุประสงค์รายกลุ่ม
- **ฟิลด์ตามไฟล์ Capex / Opex Governance Framework**: งบมีกลุ่มรายการ, กลุ่ม Priority, กลุ่ม Priority การลงทุน (CAPEX), เหตุผลสนับสนุน Priority, เจ้าของฝ่ายการเงิน (และชื่อ Owner ตามไฟล์ถ้ายังไม่ผูกกับผู้ใช้) · ตัวเลือกกลุ่มต่างๆ แก้ที่ ข้อมูลหลัก · **Import**: เลือกบริษัทที่จะนำเข้าก่อน (ในไฟล์ไม่ต้องระบุบริษัท) แล้วเลือกไฟล์ Governance Framework ได้ตรงๆ (ระบบหาแผ่นรายการจากหัวตาราง "Capex ID" / "Opex ID" และแผ่น "สรุปโปรเจ็ค" เอง นำเข้าเฉพาะแถว "อนุมัติแล้ว") · **Export**: เลือก "รูปแบบไฟล์ Governance" ได้ไฟล์หน้าตาเดียวกัน (แผ่นสรุปโปรเจ็ค / Capex Request / Opex Request ต่อบริษัท)
- **OPEX แบบงบรวมทั้งโครงการ**: ของบ OPEX โดยยังไม่มีรายละเอียด Item ได้ (เลือกโครงสร้าง "งบรวมทั้งโครงการ") ตอนขอเบิกพิมพ์ชื่อรายการเอง (ไม่ต้องเลือกหมวด) · Import ไฟล์ Governance แผ่น Opex Request นำเข้าเป็นแบบนี้
- **ฟอร์มขอเบิกใช้งบ (CAPEX และ OPEX)**: ขั้น "ข้อมูลการดำเนินการ" มีวันที่ส่งมอบ/วางบิล และวันที่กำหนดจ่ายเงิน (บังคับ) แล้วจัดรายการเป็นกลุ่ม — งบที่แยก Item: กลุ่มตาม Item · งบรวมทั้งโครงการ: แต่ละกลุ่มพิมพ์ชื่อรายการเอง + บริษัทที่ลงทุน (CAPEX) (ข้ามบริษัทกับ PCC ต้องทำ Memo) · แต่ละกลุ่มมีหลายบรรทัด Supplier (เลือกจากข้อมูลหลัก หรือ "+ เพิ่มชื่อใหม่…") · รายละเอียด · จำนวนเงิน · VAT · แถวรวมท้ายกล่อง · กล่องแนบเอกสาร · ไม่มีวัตถุประสงค์ / ผู้รับเงินด้านบน · การ์ดสรุปคำขอเบิกด้านขวา · ปุ่ม "ทำซ้ำรายการเบิก" ในหน้าคำขอ
- **ส่งออกข้อมูล (Excel)**: เมนูสำหรับผู้คุมงบ / Admin ดาวน์โหลดไฟล์ .xlsx (สร้างในเบราว์เซอร์) แยกแผ่นงาน: รูปแบบไฟล์ Governance, งบประมาณ, Item, เบิกใช้งบ, รายการในใบ, ตัดงบ-จ่ายเงิน, ปรับงบ, Plan Cashflow · กรองปีงบ / บริษัท / ประเภทงบ
- **Plan Cashflow (CAPEX)**: หลังงบเปิดใช้แล้ว ผู้สร้างงบประมาณการใช้เงินรายเดือนของแต่ละ Item (ปุ่ม "วาง Plan Cashflow" ในหน้างบ) รวมไม่เกินวงเงิน Item · หน้างบแสดงแผนเทียบยอดตัดงบจริงรายเดือน
- **เลขที่เอกสารที่ระบบออกให้**: รูปแบบ `ตัวย่อเอกสาร-ปี ค.ศ.-ลำดับ 4 หลัก` เริ่มนับใหม่ทุกปี — `REQ` คำขอเบิกใช้งบ, `CAPEX` / `OPEX` ใบเบิกใช้งบ, `MEMO-C` / `MEMO-O` บันทึกข้อความของ CAPEX / OPEX (เช่น `MEMO-C-2026-0001` · ตัวนับแยกกัน · Memo เก่าก่อนหน้านี้คงเลขเดิม `MEMO-2026-0001`), `INC` คำขอเพิ่มงบ, `TRF` โยกงบ, `DEC` ลดงบ (เช่น `CAPEX-2026-0001`) · เลขที่ฝ่ายอื่นเป็นคนออก (รหัสโครงการ / Item No. / PR / PO / เลขที่มติ / เลขที่ใบเสร็จ) ผู้ใช้กรอกเอง
- **หัวกระดาษ Memo**: โลโก้ PRECISE สีดำ (`img/logo-precise.png`) ชิดซ้าย และคำว่า Memo ชิดขวา ใช้กับทุกบริษัท · อัปโหลดโลโก้เฉพาะบริษัทได้ที่ ข้อมูลหลัก > บริษัท · ตารางหัว (เรียน/วันที่-เลขที่, เรื่อง, สำเนาถึง, อ้างอิง) กว้างกว่าเนื้อความ มีแต่เส้นแนวนอน
- **Memo แบบกรอกตามโครงเอกสาร**: Memo ขอดำเนินการใช้งบ (CAPEX): กด "ทำ Memo" ในหน้างบแล้วกรอกในหน้า Memo ที่มีช่องอยู่ในตำแหน่งเดียวกับแบบฟอร์มจริง (เรียน, วันที่, สำเนาถึง, เรื่อง, อ้างอิง, เรื่องสืบเนื่อง, เรื่องเพื่อพิจารณาลงนาม, ผู้ลงนามเสนอ, ผู้ทบทวน, ผู้พิจารณาอนุมัติ) ยอดเงินและตารางสรุประบบคำนวณจากงบ แล้วดูฉบับพิมพ์ / PDF
- **ใบเบิกใช้งบ 1 ใบใช้ได้หลาย Item** (ทั้ง CAPEX และ OPEX): เลือก Item ทีละบรรทัด ตรวจเกินงบทีละ Item และทั้งโครงการ ตัดงบตามสัดส่วนของแต่ละ Item
- **คัดลอกจากโครงการ OPEX ก่อนหน้า**: Business ที่สร้างงบ OPEX ใหม่เลือกโครงการเดิมของตนเป็นต้นแบบได้ (ปุ่ม "คัดลอก" บนฟอร์ม หรือ "คัดลอกเป็นโครงการใหม่" ในหน้างบ) ระบบดึงบริษัท หน่วยงาน กลุ่มงบ ชื่อ ปีงบ และ Item หลักพร้อมวงเงิน / VAT / GL มาใส่ฟอร์ม แก้ได้ · รหัสโครงการกรอกใหม่ · ไม่คัดลอก Item ย่อย / เอกสารอนุมัติ / ไฟล์แนบ
- **OPEX (งบดำเนินงาน — เดิมชื่อ CBS)**: ข้อมูลหัวงบกรอกเหมือน CAPEX (บริษัท, ปีงบ, รหัสโครงการ (Project No.), ชื่อโครงการ, หน่วยงาน, Business เจ้าของงบ) — **ต้องมี Item เสมอ**: *Item หลัก* (1, 2, 3 …) กำหนดพร้อมวงเงินตอนตั้งงบ ส่วน *Item ย่อย* (1.1, 2.1 …) เพิ่มได้หลังงบเปิดใช้แล้ว (ปุ่ม "จัดการ Item ย่อย" โดย Business เจ้าของงบหรือผู้คุมงบ ไม่ต้องอนุมัติซ้ำ ยอดงบรวมไม่เปลี่ยน) วงเงินรวมของ Item ย่อยต้องไม่เกิน Item หลัก และจะกำหนดวงเงินหรือไม่ก็ได้ (ไม่กำหนด = ใช้วงเงิน Item หลัก) · การขอเบิกใช้งบของ OPEX **ไม่ต้องทำ Memo** · เลขที่ใบเบิกใช้งบ OPEX เช่น `OPEX26-0001` (ในระบบยังเก็บรหัสประเภทเป็น `CBS` เพื่อให้ข้อมูลเดิมใช้ต่อได้)
  พร้อมจำนวน/หน่วย/ก่อน VAT/VAT/GL Code — รายการแม่รวมยอดจากรายการลูกอัตโนมัติ เบิกได้เฉพาะรายการล่างสุด
- **ปรับงบ / Revise CBS**: ทุกครั้งที่เปลี่ยนวงเงินหรือรายการต้องระบุเหตุผล และเก็บเป็นประวัติ (ครั้งที่ / วันที่ / โดย / ยอดรวม)

### กระบวนการขอเบิกใช้งบลงทุน (CAPEX)
1. ผู้ขอซื้อตรวจสอบงบที่ใช้ได้
2. จัดทำเอกสาร: รายการย่อย, วัตถุประสงค์, Supplier, เงื่อนไขการจ่าย, PO No. หรือ N/A และ **รายการที่ซื้อ/จ่ายได้หลายบรรทัด**
   (แต่ละบรรทัดมีก่อน VAT + VAT 7%) — ใบเบิก 1 ใบใช้กับรายการย่อยเดียว → ส่งให้ฝ่ายการเงิน
3. ฝ่ายการเงินรับเอกสารและตรวจสอบ
   - **อนุมัติ** → ออก *ใบเบิกงบประมาณ* เลขที่ `PSL26-001` (บริษัท + ปี + ลำดับ) → จบกระบวนการ
   - **ไม่อนุมัติ** → แจ้งเหตุผล → ผู้ขอซื้อ *แก้ไขและส่งใหม่* (ใช้เลขที่คำขอเดิม เก็บประวัติรอบก่อน) หรือ *ยกเลิก*
4. **จ่ายเป็นงวด**: ขอเบิกยอดเต็มครั้งเดียว แล้วการเงินบันทึกงวดจ่ายใต้ใบเบิกเดิมเมื่อได้รับบิล (เมนู "งวดจ่ายค้าง")
5. ฝ่ายบัญชีลงวันที่จ่ายจริงและแยก Asset / Expenses ของแต่ละงวด — เมื่อลงวันที่จ่ายงบจึงถูกตัดเป็น "ใช้แล้ว"

### กระบวนการขอเบิกใช้งบโครงการ (CBS)
1. หน่วยงานที่ขอซื้อตรวจสอบงบที่ใช้ได้ (แยกตามรายการต้นทุน)
2. จัดทำเอกสาร: วันที่เบิก, ผู้รับเงิน, PO (ไม่ออก PO ได้) และ **หลายบรรทัด — แต่ละบรรทัดเลือกรายการต้นทุนเองได้**
   → ได้เอกสารเลขที่ `CBS26-0001` ทันที (ไม่ต้องผ่านฝ่ายการเงิน)
3. **ใช้เกินงบของรายการได้ แต่ต้องระบุเหตุผล** — ยอดคงเหลือติดลบแสดงเป็นสีแดง "เกินงบ"
4. ถ้าทำเอกสารผิด ผู้ขอ *ยกเลิกเอกสาร* ได้เองโดยต้องระบุเหตุผล → ยอดคืนเข้างบทันที
5. ฝ่ายบัญชียืนยัน GL Code รายบรรทัด (ดึงจากรายการต้นทุนให้อัตโนมัติ) และบันทึกการจ่ายเงิน (สถานะ "จ่ายแล้ว" + วันที่จ่ายจริง) — จ่ายแล้วงบจึงถูกตัดเป็น "ใช้แล้ว"

### เงื่อนไขการตัดงบ
งบจะถูกตัดเป็น **"ใช้แล้ว"** ต่อเมื่อ **ฝ่ายบัญชีบันทึกการจ่ายเงินจริงแล้ว** เท่านั้น — ออกเอกสารแล้วยังไม่ใช่การตัดงบ
- **จองไว้**: คำขอที่รอการเงินตรวจสอบ และเอกสารที่ออกแล้วแต่บัญชียังไม่จ่าย — ยังหักออกจากยอดคงเหลือเพื่อกันการใช้ซ้ำ แต่ไม่นับเป็นใช้แล้ว
- **CAPEX**: ตัดงบทีละงวด เมื่อบัญชีลงวันที่จ่ายจริงของงวดนั้น (การแยก Asset / Expenses เป็นอีกขั้นหนึ่ง ไม่ทำให้ตัดงบเอง) งวดที่บัญชีลงวันที่จ่ายแล้วการเงินลบไม่ได้
- **CBS**: ตัดงบทั้งใบเมื่อบัญชีตั้งสถานะ "จ่ายแล้ว" และระบุวันที่จ่ายจริง
- เอกสารจะอยู่ในเมนู "รอบันทึกบัญชี" ของฝ่ายบัญชีจนกว่าจะจ่ายครบ

### ยอดคงเหลือ
- เอกสาร CAPEX ที่ส่งแล้วจะ **จองงบ** ทันที; ไม่อนุมัติหรือยกเลิกจะคืนยอดอัตโนมัติ
- CAPEX: ไม่ให้เบิกเกินคงเหลือของรายการย่อย (ต้องให้การเงินปรับงบก่อน)
- การเงินลดวงเงินรายการ CAPEX ให้ต่ำกว่ายอดที่ใช้/จองไปแล้วไม่ได้ และลบรายการที่มีการเบิกแล้วไม่ได้

### เอกสารผลลัพธ์
- **ใบเบิกงบประมาณ (CAPEX)** ตามแบบฟอร์มเดิม: รหัสโครงการ/รายการย่อย, ยอดงบ *ระดับโครงการและระดับรายการย่อย*
  (งบ / ใช้ไปก่อนขอเบิก / ขอเบิกครั้งนี้ / คงเหลือ), ข้อมูลการเบิกครั้งนี้ และช่องลงนามของผู้ขอและผู้ตรวจสอบ
- **เอกสารการเบิกขอใช้งบประมาณ (CBS)**: ยอดระดับ Job และยอดของทุกรายการต้นทุนที่อยู่ในใบ + GL Code รายบรรทัด
- ทั้งสองแบบแสดงตารางรายการที่ขอเบิกทุกบรรทัดพร้อมยอดรวม
- พิมพ์หรือบันทึกเป็น PDF เพื่อแนบกับใบขอซื้อ (PR)

โหมด Supabase: ผู้ดูแลสร้างบัญชีที่ Supabase Dashboard แล้ว **Admin** กำหนดชื่อ/บทบาทที่เมนู **ผู้ใช้และสิทธิ์**
บทบาทตั้งต้น: Admin (จัดการผู้ใช้ สิทธิ์ ข้อมูลหลัก — ไม่อนุมัติเอกสารเอง), การเงิน, บัญชี, ผู้ขอใช้งบ
แท็บ **บทบาทและสิทธิ์** เป็นตารางติ๊กว่าแต่ละบทบาททำอะไรได้ (ดูทั้งหมด / ขอเบิก / อนุมัติ CAPEX / งวดจ่าย / จัดการงบ / บัญชี / ข้อมูลหลัก / จัดการผู้ใช้) และสร้างบทบาทใหม่ได้
สิทธิ์ทั้งหมดตรวจที่ฝั่งฐานข้อมูลทุกครั้ง และมีผลทันที
ดูขั้นตอนตั้งค่าที่ [`supabase/SETUP.md`](supabase/SETUP.md) และโครงสร้างฐานข้อมูลที่ [`supabase/schema.sql`](supabase/schema.sql)

### ข้อจำกัดของต้นแบบ
- โหมดทดลอง: ข้อมูลเก็บใน `localStorage` ของเบราว์เซอร์ จึงไม่แชร์ข้ามเครื่อง/ผู้ใช้จริง และไม่มีการยืนยันตัวตน (ใช้โหมด Supabase เมื่อจะใช้งานจริง)
- ข้อมูลตัวอย่างทั้งหมดเป็นข้อมูลสมมติ — **ห้ามนำข้อมูลงบจริงขึ้น GitHub Pages** เพราะเป็นเว็บสาธารณะ
- ยังไม่มีหน้าลืม/เปลี่ยนรหัสผ่านในเว็บ (ผู้ดูแลตั้งรหัสใหม่ที่ Supabase Dashboard) และยังไม่ได้เชื่อมเลขที่เอกสารการเบิกขอใช้งบเข้ากับขั้นตอนขอซื้อ (PR)

### ปุ่มย้อนกลับ
ปุ่ม "ย้อนกลับ" (และปุ่ม "ยกเลิก" ในฟอร์ม) พากลับไป **หน้าก่อนหน้าที่เปิดมาจริง** เช่น เปิดเอกสารจากรายการคำขอจะกลับรายการคำขอ ไม่ใช่หน้ารายละเอียด
ระบบเก็บลำดับหน้าที่เปิดไว้เอง (ไม่ใช้ history ของเบราว์เซอร์ เพราะหลังส่งฟอร์มจะพากลับไปหน้าฟอร์มเดิม) — หน้าฟอร์มจะไม่ถูกนับเป็นหน้าที่ย้อนกลับมา
ถ้าเปิดลิงก์ตรงโดยไม่มีหน้าก่อนหน้า จะกลับไปหน้าต้นทางตามชนิดหน้า (เช่น เอกสาร → คำขอ, รายละเอียดงบ → รายการงบ)

### การขึ้นเว็บเวอร์ชันใหม่
ทุกครั้งที่แก้ไขแล้วจะขึ้นเว็บ ให้เปลี่ยนเลขเวอร์ชันใน `index.html` (ใน `<meta name="app-version">` และ `?v=` ของ css/js ให้ตรงกัน)
หน้าเว็บจะเช็กเลขนี้ทุกครั้งที่เปิดหรือกลับมาที่แท็บ ถ้ามีเวอร์ชันใหม่จะโหลดหน้าใหม่ให้เอง ผู้ใช้ไม่ต้องล้าง cache
